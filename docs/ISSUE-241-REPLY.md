感谢反馈。先说结论：**上游没有「关水印」这个开关**——我把它可能藏身的每一个位置都
试了一遍，全部无效。能真正做到「不带水印」的只有一条路：**换一个模型**。这条已经做成
你可以自己选的选项（见下），但它有代价，所以我没有替任何人把默认值改掉。

## 一、结论：水印不是模型画的，是网关加上去的

同一个提示词、同一个账号、同一天，两张图唯一的差别是模型：

| 模型 | 产物落盘路径 | 右下角水印 | 单价 |
|---|---|---|---|
| `hunyuan-image-alpha` | `aigc-processed/…` | **有**「AI生成 WORKBUDD>」 | 约 6 积分/张 |
| `hunyuan-image-v3.0` | `20261112/…`（日期前缀） | **无** | 约 11.1 积分/张 |

水印块是**固定像素尺寸**、不随画布缩放的（1024 边长上约 111×51 px，右边与下边各留
10 px；512 边长上约 205×98 px），国内区与国际区一致。它出现在产物文件名带
`aigc-processed` 的那些图上——也就是说这是**网关的落盘后处理**，不是模型在画里画的。
这一点决定了后面所有尝试的结局。

## 二、试过且**无效**的开关（别重复踩）

| 尝试 | 结果 |
|---|---|
| 请求体加 `watermark: false` | HTTP 200，水印照旧 |
| 请求体加 `extra_parameters.watermark: false` | HTTP 200，水印照旧 |
| 请求体加 `LogoAdd: false` | HTTP 200，水印照旧 |

又去看了官方桌面端 CLI（国内 5.9.3 / 国际 5.9.4）的实现：
`ImageService.buildBaseRequestBody` **根本没有** `watermark` 字段，`watermark:!0` 只
出现在 `VideoService` 的视频提交路径上（视频那边是**强制**带的）。`/v3/config` 的
`productFeatures` 里也没有任何水印 / logo / AIGC 相关的开关。

**所以这不是「漏了一个参数」，而是上游压根没提供这个能力。** 我不打算给你一个点了
必然无效的复选框。

## 三、已经能用的办法：卡片上把生图模型选成无水印那条

插件设置 → 能力 → 「生图模型（水印）」下拉框（**仅国内区**）：

- **默认**（组内第一个，`hunyuan-image-alpha`）：便宜、尺寸档位全、**带水印**。
- **`hunyuan-image-v3.0`**：**不带水印**，但——

代价我写在提示里，也照实说在这里：

| | 默认（alpha） | v3.0 |
|---|---|---|
| 单价 | 约 6 积分/张 | **约 11.1 积分/张**（贵约 85%） |
| 边长 | 512–2560 | **512–2048** |
| 总像素 | 约 419 万 | **约 105 万**（`1024x1024` 就顶格） |
| 竖版 `1024x1536` | 原样出 | 收窄成 **836x1254**（比例不变，实测可用） |

**默认没有改。** 换模型同时改了价格（+85%）和能力（尺寸上限掉到四分之一），这两件事
该由你决定，不该由一次升级替你做。想不带水印，就在那个下拉框里选一次，之后一直生效。

另外一个坑值得单独说：`hunyuan-image-v3.0` **只能用于文生图**。它在改图接口
（`/v2/images/edits`）上会**静默忽略你给的参考图**——请求返回 200、照扣 11.31 积分，
但出来的图和你给的那张毫无关系（实测：给一张蓝底黑十字、要求「只加一颗星」，出来是
灰底一颗星，输入图完全没进画布）。所以它没有出现在改图那一组里，改图继续用
`hunyuan-image-alpha-edit`。

## 四、国际区拿不到这个办法

`hunyuan-image-v3.0` 在国际区直接 `HTTP 400 code 14401 Image model
[hunyuan-image-v3.0] route config not found`。国际区目录里只有 `hy-image-3.5`
（约 2.16 积分），实测也带水印。所以这个选择器只在**国内区**出现；国际区目前没有
无水印的模型可选。

## 五、如果你想要的是「换成自己的水印」

那反而是另一件事，而且**上游是支持的**：`hunyuan-image-v3.0` 接受 `footnote` 字段，
会在右下角渲染你传入的文字（官方 schema 标注 `Watermark, max 16 characters
(Hunyuan)`，实测传入 `MYBRAND` 确实出现在图上）。同一个字段在
`hunyuan-image-alpha` 上没有可见效果。插件目前**没有**实现这个字段——它和本 issue 是
同一块地（画面上的附加文字），但语义相反：这是**加**水印，不是**去**水印。如果你要的
是「把 WORKBUDD 那个换成我自己的」，说一声，我按这个方向加。

## 六、需要你确认的

1. 你想要的是「**完全没有水印**」，还是「**换成我自己的水印**」？前者用模型选择就够，
   后者需要我把 `footnote` 接上。
2. 如果用 v3.0，你的常用尺寸是哪些？常见竖版/大图档位在它上面会被收窄（`1024x1536`
   → `836x1254`，`2560x1440` 直接不支持）。如果你的用途依赖大图，那可能得留在 alpha
   上，或者接受无水印但更小的画布。

## 取证方法（供复核）

全部读数来自一次性真实调用，逐条可重放：

- **模型发现**：`GET /v3/config` → `selectMediaModels(data.models, 'text-to-image')`
  → 只回 `hunyuan-image-alpha`。`hunyuan-image-v3.0` **不在目录里**，它是官方 CLI
  `resolveModel` 里写死的兜底（`h? "hunyuan-image-v3.0" : "hunyuan-image-v2.0-general-edit"`），
  实测可用，所以由插件补成候选。
- **水印判定**：不是靠肉眼。对产物做高斯模糊残差 + 16×16 网格高频密度检测，定位到
  右下角固定块，再在多个尺寸（512 / 1024）上量出它是**固定像素尺寸**而非按比例缩放。
- **尺寸边界**：v3.0 逐档实测。通过 `1024x1024`、`1024x1023`、`768x768`、`512x512`、
  `1280x720`、`1024x768`、`768x1024`、`720x1280`、`1152x896`、`896x1152`、`1280x800`、
  `1365x768`、`2048x512`、`512x2048`、`836x1254`；被拒 `1024x1536`、`1536x1024`、
  `1024x1025`、`1280x832`、`1280x960`、`1280x1280`、`2048x2048`、`2560x1440`、
  `1024x439`、`256`、`2048x513`、`2560x2560`。据此定下「边长 512–2048、总像素
  ≤1 048 576」，代码里是 `IMAGE_SIZE_LIMITS_V3`。
- **改图忽略输入图**：给一张程序生成的 768×768 蓝底黑十字（外加两条黑十字线），
  要求「保持原图，只在左上角加一颗黄星」，同时试 `768x768` 与 `1024x1024` 两种请求
  尺寸，产物都与输入图无关；对照组 `hunyuan-image-alpha-edit` 在同一次实验里正常保留
  了输入图并加上星星。两者都扣了费（6.11 / 11.31）。
- **回归**：`pnpm run check` 全绿（3474 条测试），其中本次新增 23 条：工具层 10 条、
  设置层 6 条、卡片 7 条。每条新守卫都做了变异验证——故意改坏被测代码（把 v3.0 的范围
  换回宽档、把偏好改成优先于显式参数、去掉水印提示、把默认值改成 v3.0、去掉国内区
  限制），对应测试逐条转红。

**没做到的**：没有找到任何能让 `hunyuan-image-alpha` 输出不带水印的参数组合，
也不认为存在——基于产物落盘路径的差异（`aigc-processed/` vs 日期前缀），这更像是
网关按模型分流的固定后处理，而不是请求可影响的开关。如果上游以后给 alpha 加了开关，
或者目录里下发了原生无水印的模型，插件这边只是一处 `imageSizeLimitsOf` /
`imageModelChoices` 的调整。
