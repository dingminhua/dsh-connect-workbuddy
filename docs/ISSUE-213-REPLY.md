## 一、事实：插件给每一条被扫消息都加了中性头，不是只给名单内的

你写的这段是准确的，但推论的落点错了：

> 本机安装包 `lib/host-heartbeat-*.js` 里 `UNAPPROVED_CHANNEL_OPENINGS` 只有两条固定前缀（…），`isUnapprovedChannelOpening` 是 `startsWith` 匹配。任意思考文本不会命中这两条 → 不加中性头、不扰动 → 原样发出 → 网关拦。

前半段对，箭头那一步不对。`UNAPPROVED_CHANNEL_OPENINGS` 只是**第一发**用的名单；被拒之后，救援阶梯的第一级 `forceNeutralHead()` 与名单**无关**，它读 `scansOpening(role)`——`system` 与 `assistant`（以及会被改写成 `system` 的 `developer`）——给**每一条**这样的消息的每一个文本段前面加中性头，不管开头是什么：

```ts
if (!scansOpening(message['role'])) continue
if (content.trim() === '' || startsWithNeutralHead(content)) continue
message['content'] = `${WORKBUDDY_FALLBACK_SYSTEM_PROMPT}\n\n${content}`
```

这段在 `461ca3c`，`git tag --contains 461ca3c` 从 **v4.15.1** 起覆盖之后**所有** tag，所以 5.11.0 必然带着它。也就是说：**你报的那次失败发生在第三发，前面所有被扫消息（含那三条思考文本）都已经有中性头了**；而且这不是我事后从代码里推的——你自己贴的报错原文里就写着：

> 插件已加中性头）… 插件已用强制中性头与一次不可见扰动与一次密集不可见扰动重试过

三级阶梯全跑过、全被拒。所以「没加头所以被拦」不是这次的机制。

## 二、为什么报错会让你这么想：三处文案，我把「我看到的」写成了「唯一可能的」

证据块读的是**宿主原始请求**（`channelEvidenceText(raw)`），不是重试后那一发——这是刻意的：如果读重试体，每条开头的第一行都会是插件自己的中性头，你就看不到「是哪条消息被扫了」。代价是每条的标签只描述**第一发**，而旧文案把它写成了断言：

1. 「（不在插件已知名单里，**网关可能新增了词条**）」——「不在名单里」只说明**首行**不在那份快照里，既不等于整条消息不在名单里，更不等于它原样发出。
2. 「网关匹配的是每一条 system 与 assistant 消息的**开头**」——漏了一半：issue #125 的实测是「开头做前缀匹配 **+ 全文本做大小写不敏感精确子串匹配**」。
3. 结尾「若上面标着「不在插件已知名单里」的开头来自宿主或其他插件，请修改该提示」——把一条首行判据写成了行动建议。

你对这三条的反应（去改宿主提示、以为没归一化）是**按字面意思做出的正确反应**。所以这一节不写「文档已澄清」，而是改了文案（`713437d`）：

- 标签 → 「（不在插件已知名单里，仅指首行）」；
- 「匹配开头」→「开头做前缀匹配，正文做精确子串匹配」；
- 结尾 → 「只说明该消息的首行不是已知指纹，既不表示这条消息没被处理，也不表示它一定有问题；如果这些消息确实有问题，命中的更可能是中段的某一句」；
- **只在第三级真跑过时**才追加「这次重试里每一条被扫描消息都已经加了中性头，仍然被拒，说明卡点不在这些开头本身」——由 `retriedWithForcedHead` 决定，没跑过就不出现（有测试钉住「没跑过不许说」）。

## 三、那这次的真正原因是什么

按现有实测证据，最可能的是**同族的新形态**，而不是漏了名单：

- #125 的实测：网关对同一份请求做**前缀 + 精确子串**两道匹配，活的 DSH 提示词里有三处 span，三处全改才 200。插件现在在请求路径就按词界打断身份从句（+0.26% 字节），所以「首行是不是 agent 套话」这一层已经基本不构成卡点。
- 你这次被拒的形态里，system 是已知命中（已加头）、三条 assistant 是**任意思考文本**（也加了头），四次都 400 → 卡点要么落在某条消息的**中段**（首行判据看不见），要么是判定不只看内容（例如「assistant 消息的形状像内部思考」）。
- 后一种如果成立，你的建议 **2（发送历史前剥离 reasoning 块）** 是唯一能根治的方向：官方客户端的历史里大概率没有思考文本。但这是一处会改变请求字节的默认行为，我不打算在未实测的情况下默认打开——**可以做成可选开关**（现有 `channel-continue` / 扰动策略那套配置可以复用），你先在本地验证。
