# 回复 issue #214

> 感谢这份报告——三个数据源（接口 / 卡片 / 磁盘）的对照表、真实扣费反推、
> 以及 UA 双通道那条，是我在这个 issue 上花时间最少的侦察阶段。两半都确认了，

## 先回答你的问题：升到 5.18.0 后 `glm-5.3` 会显示 0.69、`hy4-preview` 会显示 0.29 吗？

**不会。你的判断是对的，而且你只看到了一半。**

5.18.0 确实修了 `applySelection`（你现在看到的 `hasLiveRoster()` 守卫，`src/index.ts:2094`）。
但**卡片读的是另一条路**：`usage` 路由 → `displayModels()`，而那里当时**没有**这道
守卫，仍然把 `catalog.current()`（冷启动时正是兜底表）当作 live 传进 `resolveRoster`。

所以升到 5.18.0 之后：`glm-5.3` 仍会显示 **0.79**，`hy4-preview` 仍会显示 **0.00**。
你问的这条，答案是否定的。

## 根因一：兜底表不该有价格

`FALLBACK_WORKBUDDY_MODELS_GLOBAL` 在 2026-09-11 抓取时把倍率一起硬编码了。
它经构造函数灌进 `current()`，`resolveRoster` 只判「非空」分不出静态表和上游答案，
`overlayLiveCapabilities` 又让 live 侧拥有 `creditMultiplier`——于是兜底表盖住了
你保存的值。你的推断完全正确，包括「26 行里只有 2 行错 = saved 与兜底表取值不同
的全部交集」这条判据。

**修法不是我原来想的那样（加守卫），而是把价格从表里删掉。**

价格是「此刻」的事实，而一个静态模块永远不知道此刻是何时。这张表在 2026-11-04
就已经和上游差了 0.10，它不是「兜底」，它是**一个会过期的断言**。现在表里只有
id / 名称 / 窗口（这些老化得慢，而且是「首帧 provider 不为空」的真正理由），
**一个倍率都没有**——没写价就是不知道，卡片不画倍率，`pickFreeModel()` 也绝不会
再把「不知道」当成「免费」。

国内版表一直是这个形状，同一个理由。守卫我还是加上了，但它现在是纵深防御而不是
修复（表里没有 live-owned 字段了，去掉守卫测试仍绿）——留着是因为下一个往表里加
字段的人否则会重演这件事。测试文件里明写了这一点，我不想让一条测试假装在守它
其实守不住的东西。

## 根因二：`models/refresh` 丢掉了它唯一的产出

你写「对用户来说『刷新』是个无效按钮」，这正是它的实际形态。它只
`json(res, 200, { models })`，什么都不写。

现在：路由**先落盘再应答**，写入复用已有的 `repairRegionCatalog`（它懂合并规则，
不会碰另一个区域和你这个槽位里的其它字段）；**写不进去就返回 500**，而不是给你
一个「已经记住」的 200——你抱怨的正是「看得见新值、卡片不会变」，一个假装成功的
200 只会让它更难发现。

**但你的勾选我没有替你保存。** `enabledModelIds`、图片勾选、上下文预算、默认推理
档仍然是草稿，仍然要点保存。理由很直接：你卡片里的草稿本来就包含没勾的模型，一并
提交等于替用户按了保存。所以语义变成——**目录与倍率随刷新即刻生效，选择仍是草稿**。
两个 README 和 DESIGN.md 里「刷新是草稿操作」那句已按这个改写了。

## 关于你附的上游计费实测

这段比 issue 本身更有价值，我按它记了三件事：

1. **`credits` 本身不可信**，所以插件永远不该把它当作「免费」的依据——`x0.00`
   在 `pickFreeModel()` 里是「去挑它做探针」的许可，一个假的零要花钱。
2. **同一个 `/v3/config` 按 UA 给两份价目**，我们走 APP 通道（`PRODUCT_UA`）是对的，
   你测到实际扣的是 0.11（APP 侧）而不是 0.03（CLI 侧），这条我在代码注释里指到了。
3. 「标免费实则收费」这类，**插件能保证的是「不声称」**，不能保证「上游不说谎」。
   这是这次修法的边界，我写清楚而不是假装解决了。
