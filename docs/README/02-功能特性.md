## 功能特性

- **配置在「设置 → WorkBuddy」** —— 设置面板左侧导航里与「账号与余额 / 通用设置 / 模型 / 插件」并列的一页。5.19.0 起**插件市场里那个 bundle 详情页不再显示配置卡片**：同一份配置只留这一个编辑入口。页面顶部是图标、标题与一句话简介，往下依次是国内版 / 国际版两个 tab、五个分栏，以及各自的保存与放弃。
- **双供应商并行接入（国内版 + 国际版）** —— 国内版注册为 `workbuddy` provider（`GLM-5.3`、`DeepSeek-V4-Pro`、`Kimi-K3`、`MiniMax-M3`、`Hy3` 等），国际版注册为 `workbuddy-global` provider（`GPT-5.6`、`Gemini-3.5-Flash`、`GLM-5.3`、`Kimi-K3` 等）。**有账号的区域其模型会出现在 DSH 模型选择器里**：两边都有账号时两组同时可选，不同会话可以各选一边，互不干扰。**本机没有账号的区域不列出任何模型**（该区域一个请求也发不出去，列出来只会点到就失败）；只要在该区域登录一次，「重新检测账号」或重启后模型就会自动出现——provider 本身始终注册着，因为它的设置页正是登录的入口（重新检测在账号池区块里）。模型名内嵌上游积分倍率（如 `GLM-5.3 · x0.79`），与 WorkBuddy 自身模型菜单一致；**活动时段显示的是折后价**——「夜间折扣」开着的时候，卡片与选择器上的数字一起变成 `x0.06`，活动一过自动回到原价，不需要重启（#120）。
- **设置页 tab 切换** —— 设置页顶部为「国内版 / 国际版」两个 tab，各含独立的账号池与模型管理；每个 tab 的账号、目录、勾选与未保存草稿完全隔离——在一个 tab 里切账号或刷新模型，不会触碰另一边的运行时目录与会话。
- **可单独关闭任一版本供应商** —— 每个 tab 右侧有一个勾选框（默认都勾选）。**取消勾选即把该供应商从 DSH 模型选择器里彻底撤掉**（不是只藏起 tab）：它的路由与「设置 → 模型」页的目录条目一并摘除，启动时也不再为它发无用请求。账号、积分、目录与勾选**全部保留**，重新勾选即完整恢复。典型用法是「我根本用不到国际版」——关掉它，让选择器干净。注意：若某会话此前选中的正是被关闭供应商的模型，该会话再调用会报 `NO_ADAPTER`，卡片会在关闭态的 tab 上明确提示这一点，不会静默失败。
- **设置页分栏：账号 / 模型 / 能力 / 诊断** —— 原来这一页是一列 3000 多像素的长页，把两类互不相干的事情混排在一起：**运维账号**（谁在服务、还剩多少、切换顺序、签到日志）与**编辑目录**（勾模型、上下文预算、推理档、关闭思考）。它们连提交语义都不同——账号改动点一下即生效，目录改动是草稿、必须点保存——所以「保存」按钮常常离它要保存的东西隔着三屏。现在分栏，一栏只做一件事；**切栏既不会重新拉取，也不会丢掉未保存的目录草稿**（非活动栏留在页面里，只是通过 `hidden` 不可见，因此也不进入无障碍树）。第三栏「能力」放的是**授权类开关**——允许调用本机 CodeBuddy CLI、允许模型自主生图、积分读数显示在哪——它们点一下即生效、从不经过保存，而且每一个都留着长自己子选项的位置（CLI 的工作目录、生图的尺寸或价格上限），所以不挤在账号表格上方那一小条里。第四栏「诊断」是只读的事实表：当前区域、上游域名、真正在服务的账号名、登录有效期、目录里共几个模型、启用了几个、账号池开关，以及上游最近一次错误的**原文**（原样引用，不翻译、不概括）——这一栏存在的唯一理由就是能被整段贴进问题反馈，所以里面没有任何会改设置的控件。
- **刷新频率（`pollIntervalMs`，默认 5 分钟）** —— 卡片多久重读一次账号表。**这是一次真实的请求量决定**：每次刷新要为池内每个账号各读一次积分（`/v2/billing/meter/get-user-resource`）和一次签到状态（`/v2/billing/meter/checkin-activity-status`），所以 4 个账号的池子按旧的固定 60 秒算，一天约 11,520 个请求——而这些数字本来动得很慢。默认改成 **5 分钟**（约为原来的 1/5），「能力」栏给五档：1 / 5 / 10 / 30 / 60 分钟，点一下即生效、不走保存。**输入框的账号面板跟随同一个值**：此前它自己写死 60 秒，只是「碰巧」等于卡片的 60 秒，两边一旦改动就会对同一个账号给出不同说法（面板还画着「模型繁忙」、卡片已经说恢复正常）——现在只有一个间隔，改一处两处一起变。**取值是封闭的五档**：配置文件里手写的 `0` 或别的数字一律回落到默认值，因为「不刷新」和「疯狂刷新」都不是用户想要的，而这个数字直接驱动 `setInterval`。
- **可选：侧边栏入口（`sidebarPanel`，默认关闭）** —— 在 DSH 侧边栏加一行 WorkBuddy，点开就是**这张卡片的整页版**（左上有「返回会话」）。分栏挤在设置面板那 800px 里时，账号表格、模型目录与诊断原文都只有半屏宽；整页版把同一批东西摊到整栏。**默认关闭**：这一行占的是**所有已安装插件共用的全局侧边栏座位**，而「设置 → WorkBuddy」本来就能打开同一页，一次升级不该替用户占这个位置。开关在「能力」栏，**勾上即出现、取消即消失，不走保存**——与这一栏其它授权类开关一致。
  - **关掉时是把注册注销，不是渲染空组件**：侧边栏导航行是用槽位**条目元数据**（`label` + 图标）拼的，组件返回 `null` 只会得到一颗**空白但仍可点**的按钮。所以决策点在 `apply`（`src/client/panel-switch.ts` 是卡片与入口之间的接缝），关掉即 `dispose`。
  - **首屏状态问宿主，不问浏览器里的设置镜像**：那份镜像在部分 0.1.7 上是陈的，且只在命名空间**边缘**触发、不在**值变化**时触发——一份陈的 `false` 会让这一行整个会话都不出现，且没有任何事件来纠正它。所以种子读宿主自己的答案（usage 文档的 `sidebarPanelEnabled`）。
  - **开着面板时关掉，中间栏自己回对话**（`ui-layout` 丢掉已不存在的 `activePanelId`），不需要插件去导航。macOS 实测记录见 [docs/MAC-VERIFY-PR188-REPORT.md](../../docs/MAC-VERIFY-PR188-REPORT.md)，验证清单见 [docs/MAC-VERIFY-PR188.md](../../docs/MAC-VERIFY-PR188.md)。
- **模型管理** —— 从上游刷新完整模型目录，逐项勾选启用或禁用；**勾选是草稿，点保存才生效**（issue #214）。目录与价格不等人：刷新会把这次读到的目录**直接记下来并立刻生效**，因为价格不属于草稿——上游倍率随时会变，把新价锁在草稿里意味着卡片继续显示旧价、`/usage` 与刷新按钮各说一套（报告者实测：刷新得 `glm-5.3` 0.69，卡片却仍显示 0.79）。所以**目录与倍率**随刷新即刻落盘、即刻生效，**你的勾选、上下文预算、图片勾选与默认推理档**仍然只在点保存时提交；刷新不会替你把没保存的改动一起写下去。上游同时给出积分倍率、上下文/输出上限与推理档位；**每个模型行上有一个「默认推理强度」选择器**（issue #179）：请求未指定档位时该模型用哪一档——新对话、压缩摘要、会话标题都属于这类请求。选项就是该模型自己声明的那些档位（名册里 `deepseek`/`glm-5.3` 是 `low/high/max`，`glm-5.2` 是 `high/xhigh`，`space-bunny` 有五个，所以只能逐模型选、不能全局一个值），第一项会写明真正会用的那一档——括号里先是上游为这个模型声明的档位，上游没声明时则是该模型自己的**中档**（不是最弱的那一档，免得默认把思考调低）。**这一行同时也是原来那行只读「推理强度：…」的替代**——选择器已经列全了档位，不必再多说一遍。**「关闭思考」不在这里**，它仍是下面那个 `off` 勾选框的职责。**图片输入按核验表判定**：刷新时只有核验表收录为原生多模态的模型才自动勾选，写明纯文本的不勾，**没有资料的 id 一律按「未核实」不猜**（上游的 `supportsImages` 是平台侧声明，不等于模型能看图，不参与判定）。核验表分两档证据——厂商文档（13 条）与**上游目录自述**（2 条：`space-bunny`、`minimax-m3.1-flash`，各自的描述里写着「原生多模态」）——但新增 id 仍要求厂商来源，详见 [docs/DESIGN.md](../../docs/DESIGN.md) 的「图片输入」一节。用户仍可随时手动勾选，勾选状态保存在本地。**每个模型行还有「可关闭思考」（`off`）勾选框**：决定要不要为该模型提供「完全关闭思考」这一档位。默认由内置复核名单给出（上游声称可关闭、实测却对它返回 HTTP 400 的 9 个模型默认不勾），你可以按模型改勾/取消——**取消**用于当前不需要该档位的模型；**名单内那 9 个模型不可勾选**（行上标「拒绝 off」，悬停有说明）：该档位被勾上后不只是多一个选项，pi-ai 会把它当作**所有未指定档位请求的默认值**，压缩摘要请求正属于这一类，勾一次等于让该模型的每一次 `/compact` 都 400 / 11133（issue #83）。名单外的模型仍完全由你的勾选与自身声明决定；首次保存即写入你的勾选，之后不再重算。

- **模型行上的活动徽标** —— 上游的模型目录里带着活动信息（免费试用、夜间折扣、限时免费、订阅优先等），插件**不新增任何请求**（复用刷新模型时本来就会拉的那份目录配置），直接在模型行上画一枚胶囊徽标：颜色与文案都由上游给出，悬停能看到上游的活动说明、活动的起止日期与每日生效时段（例如「夜间 23:00–7:50」）。**徽标是「此刻」的函数**：活动只在它自己声明的时间窗内显示，窗口一关徽标就自己消失；跨零点的时段按上游声明的时区判断；同一个模型命中多条活动时只画优先级最高的那条。上游没给结束时间的权益标记（如「订阅优先」）则常驻，直到上游把它下架。**徽标只是提示，不改变模型行为**——它标注的是上游此刻给出的活动与折扣，不替你做选择。**同一枚徽标也出现在 DSH 的模型选择器里**：菜单每一行都在模型名之后、队列图标之前画同样的胶囊 —— 菜单行用上游的短词（「夜间」「限免」），输入框旁那个触发器用完整词（「夜间折扣」「独家限免」）；判定用的是同一份数据、同一个时钟，因为选模型的那一屏正好是最该看到「现在免费吗」的地方。（两个区域的上游目录都下发活动字段：国内版按 App 身份读 `/v3/config` 时带 8 条促销 + 1 条等级标记，国际版带 5 条 + 1 条；取证与判定规则见 [docs/PROMO_BADGE.md](../../docs/PROMO_BADGE.md)。）
- **模型行上的繁忙程度（仅国内版）** —— 上游另有一条只读探针（`POST /v2/chat/busy`，一次最多 50 个 id，免费、不动账号状态）回答「这个模型此刻多忙」，插件在每次刷新目录时顺带问一次，把等级画成模型名旁边的一枚小人图标：排队人数 = 小人个数（正常 1 个黄人 / 轻微拥堵 2 个橙人 / 极度拥堵 3 个红人），**空闲**则是一枚**绿色小火箭**（没人排队 = 可以全速跑）——空闲不画成「绿色的 1 个人」，因为 12px 下「没人等」与「有 1 个人在等」必须一眼分开；**不可用**是一个划掉的小人。探针没回答的 `unknown` **一律不画**，**「没被告知」不会被当成「一切正常」**；颜色跟随主题，`title` 悬停文字（「极度拥堵」四个字）仍在。**等级不落盘**：目录是能活过重启的事实，负载只是那一分钟的事实，所以等级只盖在运行时目录上、随进程消失，探针失败只记一条 warn，绝不挡住目录刷新。国内版实测这条探针在 CLI 与 App 两种身份下答案逐字节相同，50 个 id 的上限也真实存在（62 个 → HTTP 400），19 个模型 186 ms 返回。**国际版没有这个徽标，因为国际网关根本没有这条接口** —— 实测 `www.workbuddy.ai` 对 `/v2/chat/busy` 回 **404**（`/v3/chat/busy`、`/v2/models/busy` 等同族路径也全是 404），而同一份凭据读它的 `/v3/config` 正常返回 28 个模型、**没有任何负载/排队字段**。这不是本插件没实现，也不是配置或权限问题：**上游国际版从未提供这个数据**。所以国际版只显示模型名与活动徽标，探针那条请求失败后安静退化成「没有徽标」，不会挡住模型列表，也不会用延迟或积分去猜一个「忙不忙」。
- **排队时说清楚你排在第几位** —— 上游用三个业务码表达排队（`6020` 等待、`6021` 队列满、`6022` 已达上限）。撞上它们时，插件不再给一句上游报错，而是「模型排队中：你排在第 8777 位，队列共 9021 个请求。请稍后重新发送这条消息，或换一个模型」。**排队不会触发换号**：队列跟随的是模型与平台级的队伍，换个账号拿到的还是同一个位次，所以这里既不走账号池也不额外烧请求（上游 `/v2/chat/queue/status` 回的 `message` 是 i18n key 而不是人话，插件因此从不转述它，只用自己的措辞）。**排队不会自动重发，也不会被自动重试**——插件没有排队轮询循环（它需要排队答案在 OpenAI 兼容通道上的真实信封，没测到就不写），并且明确告诉宿主不要重试（`x-should-retry: false`）：一次排队在几千位之后，重试十几次也轮不到，只会把真实请求白白花掉。位次报出来，由你决定是重发还是换模型。
- **模型可用性测试（含冷却恢复时间）** —— 限量模型的冷却时间过去只能靠反复试错去猜。现在每个模型行有一个「测试」按钮，直接告诉你它此刻能否使用、不能用时何时恢复。**它发的是一条真实体积的请求（约 25k 输入 token）**，而不是「发个 ping 看通不通」——因为上游的限流**按请求体积触发**（实测约 20k 能过、约 30k 被拒），小请求看着正常、长对话里却可能每次都被拒，那正是「测试通过、实际被限」的来源。**恢复时间的来源**：上游的 429 **不带** `Retry-After` 响应头（也没有 `X-RateLimit-*`），但它把重置时间写在**响应体**里——`{"code":6004,"msg":"…将在 2026-09-30 02:30:30 UTC+8 重置…"}`。插件从响应体解析该时间（并按其声明的 UTC 偏移换算，不受你本机时区影响），因此卡片能直接显示「✗ 被限流 · 2026/9/30 02:30:30 之后可再用」。三处来源都没说时，插件**不编造倒计时**，如实显示「上游未给出何时恢复」。限流**不会**去借月周期包的刷新时间（那会让人为几秒的限流去等几周）。**成功即无冷却**：这个网关在 200 响应上也会带 `Retry-After`，值是账号月度积分包的刷新时刻（实测 `2026-11-01 00:00 +08:00`），它不是「你在此之前不能用」——所以成功的行只显示「✓ 可用」，绝不附「之后可再用」；旧版本已经写进文件的那类记录会在读取时自动治愈。探测在后台发起，**凭据不会传到页面**；结果不写入设置，也不改变你已保存的勾选。

  **两点需要知道**：① **它真的花钱**——实测一次报 `credit` 0.02（被限流时直接 429，几乎不花）。因此**只能按单个模型手工点**，没有「测试已勾选」这类批量按钮：一次覆盖整个列表就是一次不可控支出（服务端也据此**只接受单个模型**，多模型请求会被拒）。② 上游虽宣称 1M 上下文，但节流线远低于此；插件按模型的**原生窗口**向 DSH 宣称（3.5.0 起不再默认压到 200K），所以 DSH 很晚才压缩对话——长会话撞限流是这条机制的直接结果。想让 DSH 更早压缩，就在模型行上手动设一个「DSH 上下文预算」上限（可选 200K / 500K / 模型原生窗口）。**这三档里哪一个是「当前」由后端算出的实际窗口决定**（issue #215）：没设过预算时选中的就是模型原生窗口，因为 DSH 拿到的正是它；「模型原生窗口」这一档对应的是**没有上限**，选中它会把这个模型的预算条目删掉，而不是写一个恰好等于窗口的数字——这样上游日后调大该模型的窗口时，这一档会跟着变大。
- **生图工具 `workbuddy_draw_image`（国内版 / 国际版，默认关闭，逐区授权）** —— 把 WorkBuddy 的文生图能力交给 agent：你在对话里说「帮我画一只在窗台上晒太阳的猫」，模型自己就会调用这个工具，画完把图贴回来。**默认不开启**，因为这是本插件里唯一一项「由模型自己决定花钱」的能力：国内区约 5.71 积分一张、国际区约 0.03 积分一张，而宿主没有「调用前先确认」的机制。想用就去卡片「能力」栏那个区勾上「允许模型自主生图」；不勾的时候这个工具**根本不会注册**，模型看不到它，也就不会发起注定失败的调用。**两个区都能用，但用的是两个不同的模型**：国内区 `hunyuan-image-alpha`（5.71 积分/张），国际区 `hy-image-3.5`（0.03 积分/张，2026-10-25 实测）。两者的积分池彼此独立，**5.71 与 0.03 不是同一张图的跨区差价**，只是一个读数，别拿它做汇率换算。勾选是**逐区**的：在一个 tab 里勾上只授权那一区的账号；两区都勾着时优先国内区（与升级前的行为一致）。**端点与请求体照抄官方 CLI 的 ImageService**（`POST /v2/images/generations`），产物是 24 小时有效的 COS 签名 URL，插件会提醒你及时下载。**同一个工具也能改图**：给 `image` 参数（**字符串数组**，元素可以是本地路径 / `file://` / `http(s)` / data URL / 裸 base64，上限 8 MB；一张图也要写成 `["/abs/a.png"]`）就自动切到 `POST /v2/images/edits` 并用带 `image-to-image` 标签的模型（国内 `hunyuan-image-alpha-edit`、国际 `hy-image-3.5`），不给就是文生图——**模式由「有没有图」唯一决定，没有 `mode` 参数**。输入图只归一成上游要的 data URL，**不缩放、不裁剪、不转格式**；读不到图、格式错、超限都在发请求之前报错，不算一次花钱的失败。**`size` 是必填参数，不写就直接报错**——早期版本不填会静默按 `1024x1024` 出图，模型于是学会了「什么都不写，让它自己猜」，最后连横竖都没交代就出一张方图。现在写成「宽x高」或 `auto`（工具描述里按「具体像素 → 比例词 → 档位词 → 改图 `auto` → 用途 → 表外比例 → 只提方向 → 默认档」八阶顺序命中，命中即停；比例词单列一阶是因为「9:16」「3:4」既不是像素也不是档位，「改成 9:16」曾经会掉进 `auto` 那阶、输出仍是横图还不报错；这一阶里每个比例词只对应一个像素值——旧稿写「『9:16』`1440x2560` 或 `1024x1536` 按长边需求选」，而后一个其实是 2:3，选它等于对用户说谎；用途表每行自带方向、命中一行就用它，只有用户另外明说的方向与该行不符时才改——第十二轮补的那条链尾裁决句「用途和方向同时出现时按方向」第十三轮被删了，因为它自己造了双解：「做张手机壁纸，横着看的那种」会同时命中用途表的竖档和裁决句的横档；现在方向并进表里，「配张图，要横的」直接给 `1536x1024`，不会出成方图；第十五轮又拆出两阶——「表外比例」（4:5、21:9、5:4）不再写「套最近档」，而是**给算式**（长边尽量取 2560、宽乘高不超 4,194,304，超了就把长边往下取、另一边按比例算完取整：21:9 → `2560x1097`，4:5 → `1831x2289`，回复里写明实际出的比例），「只提了方向」单独成一阶统管所有方向词（横 `1536x1024` / 竖 `1024x1536` / 方 `1024x1024`），④ 与 ⑤ 都只留引用——**引用悬空比重复更危险：重复最多是不一致，悬空是那一条请求根本没有出口**；第十七轮又补三处：`1080P` / `720P` 各给横竖两个值（只写 `1920x1080` 时「1080P 手机壁纸」只能落横图，与「手机壁纸算竖」正面冲突）、`①` 步明说「规整这一步是你自己做」（schema 的 `pattern` 只收 `x`/`X`/`×`，带空格或 `*`、`by` 的值会被宿主直接拒掉）、`⑥` 表外比例的例子改成能被算法复核的 `21:9 → 2560x1097` 与 `4:5 → 1831x2289`——旧例子 `1600x2000` 长边既不是「尽量 2560」、面积也只有 3.2M，照着算和照着抄得到两个不同答案）：合法范围是两边各 512–2560 像素、宽乘高不超过约 419 万像素（2026-10-25 逐档实测：`1024x1536` / `2048x2048` / `2048x1536` / `2560x1440` / `2560x1600` 都成功且输出宽高与请求一致；`2560x2560` 起被直接拒绝），**越界不再报错**——`fitIntoRange()` 会按「`2560/长边`」与「`√(4194304/面积)`」中更小的比例等比缩/放后照常出图，并在 `hint` 里写明「按你给的 X 缩放成 WxH」，同时用 `requestedSize` 回带你原本写的值（写 `auto` 时就是 `auto`），所以「用户要 4K、实际出 2560x1440 档」这件事可以被程序识别、不必正则抠散文（`4K` 在描述里不设独立档：横竖方分别与 2K 同档，因为工具上限是**单边 2560、面积 4,194,304**，写不出真 4K——上限只能用这一组数说，`2048x2048` 才是顶格的那一档）。`region` 与 `size` 都在输出的 `required` 里（两个都由工具自己算，一定在），想按区记账或按尺寸做后处理直接读字段即可。**改图（带 `image`）推荐直接写 `size: "auto"`**：工具会从图片字节里解出第一张的宽高（PNG / JPEG / GIF / WEBP），按同比例给一个长边 1024–1536 的画布（`1600x900` → `1536x864`），模型看不到原图也不必猜比例——只有比对 5:1 更细长、等比缩数学上解不出合法值时，才退回方向常用档并在 `hint` 里写明「比例有变化」。**改图如果写了具体比例（不是 `auto`），裁切/留白这件事要在调用前说**：模型调用前量不到输入图比例，事后问「要不要改用 auto」等于先用掉一次积分再问——现在的写法是「先说一句会按这个比例裁切/留白、原版式可能被切，他同意再调」。本地因此只剩一种尺寸失败：比例极端到缩不出合法值（`INVALID_ARGS`，不扣积分）。再大只能走超分，单纯调参数已经到顶。**它真的花钱**，所以工具描述第二段就把价目写出来——国内版约 5.71 积分/张、国际版约 0.03 积分/张（同一计量单位、相差约 190 倍），模型和你开局就知道这一张多少钱，并且知道「走哪个区这一次改不了、也查不到，只能以返回的 `region` 为准」（所以描述里不要求模型在调用前报价，只要求如实报两个区、并点明差约 190 倍）；真实扣费仍以返回的 `credit` 为准，结果里同时写明**这次走的是国内版还是国际版**、用的哪个模型、实际扣了多少积分（区域从凭据 domain 现算，两区都开着时优先国内版）。描述里不点名具体模型 id，免得模型主动去猜——`model` 一般留空最稳；失败后有 30 秒冷却（但参数写错、没登录、模型不存在这三类一分钱没花，不进冷却），也不提供「一次画四张」这类不可控支出的参数。工具定义是手写的 raw JSON Schema，**没有引入任何新依赖**。第十九轮又收了三处「同一件事两个口径」：① 尺寸链的入口加了**主体门禁**——主体没问清之前整条链一条都不许走（旧稿 (a) 让他先问「想画什么」、第 2 阶又已经把 `2560x1440` 填好，「随便画个 `16:9` 的」于是自编主体扣一次费）；② 用途表补了**方行遇方向**那一支（配图是方行，旧稿只写「横行要竖」「竖行要横」，「给这篇文章配张图，要横的」无定义、会填 `1024x1024` 与同段例子 `1536x1024` 打架）；③ **批量只剩一张同意卡**——旧稿开头让「先报张数和总价」、紧接着又让「多版挑一张先出 1 张」，用户批的是 4 张预算、拿到 1 张；现在统一成「先出 1 张给你看，满意再按张补后面的，每张单独计费」。同时把「重试」写成一次**新的计费决策**（`INVALID_ARGS` / `NOT_LOGGED_IN` 改完直接重试，其余情形重试前按两档重新报价取同意），并把「已经拿到过 `credit`」收紧成「**本次调用**拿到过」——190 倍差正是跨区、跨模型产生的，拿上一次的单价报这一次等于报错价。第二十、二十一轮又收了三处**同一事实两个出口**：① 用户说「我这张是 1600x900」时，① 的触发词（数字 + x）会先吞掉它、脚注又说该写 `auto`——现在第 4 阶第一句先分类「这是输出尺寸还是输入图尺寸」，输入尺寸永远不填进 `size`；② 「单张不必为『要不要花一次积分』单独请示」这句被两个盲读子代理判成最危险的一句（它把授权扩张到不等裁切确认也能扣费），换成一份**五条清单**（超过一张 / 改变原图版式 / 要真调才能报价 / 主体没定 / 用户要的做不到）——命中两条以上合成一次问完，都不成立才直接调；③ 主体例子原来「秋季新品静物」是正例、「秋季新品」是反例，而用户原话正是后者，现在换成「一束向日葵」。第二十二轮又收掉三处「照字面执行必然出错」：① **4K 不再既算档位词又算「做不到」**——七条第 5 条原来写「用户要的东西本工具做不到（真 4K…）」要先停，第 3 阶又让「照 2K 填、出完再说明」直接调，同一句「来张 4K 壁纸」两个出口；现在清单里只留「明确要 `3840x2160` 这类超过 2560 的像素」——**档位词是用户的说法，不是他的诉求**。② **改图的「告知」与「请示」钉进同一个句号**：(b) 说单张只告知、④ 说裁切要等同意，「把这张 `1600x900` 改成 `9:16`」同时命中两条，裁切不可逆、价格可逆，不能共用一句话。③ **「4 张要多少钱」有了分支**：只说张数没说同异时，先问「要一样的还是各不相同的」。另修 ③ 的 4K 算术错（`3840x2160` 是 16:9，等比缩是 `2560x1440`；`2560x1350` 属于`4096x2160`），并把 ⑤ 的「方向 × 用途」三支枚举收成「冲突就交换宽高、相同就照这一行走」。第二十二轮第三批又把三处「作用域/台词」收掉：① **多图三态从「超过一张」的门里提出来**——「要一样就做不到、不报价不调用」原来写在「要超过一张时先判」这道门内，用户说「上次那张再画一遍，要一样」只要 1 张、门不成立，「直接调」与「不调用」两条都逐字可读（0 次或 1 次扣费），现在改成「跟要几张无关，先判要的是『一样』还是『不同』」，并把「没有 seed、不存历史、不能重放」提为全局事实；② **改图的 prompt 台词只剩一套**——旧稿一处让写「只换画布」、另一处让只写「保持主体和光线不变」，而「只换画布」是事实错误（工具会裁切或留白，画面内容会变）；③ **4K 那句话术收窄成条件句**——只有用户提的档位超出上限时才补「最长边 2560」，只说 2K 的用户不再被告知「出不了真 4K」。另把「只提了方向」从用途表里拆走（「竖版海报」要说到「海报」才算用途，只说「竖版」是方向词），并给第 4 阶补一句「同一句里既有输入图尺寸又有比例时，输入那个数不参与匹配」——旧派发顺序会让「这张 4000x1000 的图改成 4:5」填成 4000x1000、被缩成 `2560x640`，方向相反还照扣费。取证、协议与联调记录见 [docs/IMAGE_GEN.md](../../docs/IMAGE_GEN.md)。
- **视频生成工具 `workbuddy_draw_video`（国内版 / 国际版，默认关闭，逐区授权）** —— 把 WorkBuddy 的视频能力交给 agent：「帮我把这段描述做成 5 秒视频」，模型自己调用工具，跑完把 **mp4 的本地路径**贴回来（视频是二进制，只回 `file://` 路径并渲染成链接，不塞进对话体）。**它和生图不是一个形状**：视频是**异步任务**，`POST /v2/videos/generations` 只回一个 `taskId`，插件再轮询 `POST /v2/videos/tasks` 直到 `completed`（5 秒一次、上限 10 分钟），最后把产物下载到 `os.tmpdir()/workbuddy-video-gen/`。**同一个工具也做图生视频**：给 `image` 参数（字符串或单元素字符串数组、**只收一张**——与生图那边「纯数组、可多张」不同）就切到 `image-to-video` 标签组并按输入图决定比例，不给就是文生视频——**模式由「有没有图」唯一决定**。其余参数：`seconds`（默认 5，须在该模型 `[min,max]` 内）、`resolution`（不在模型 `resolutions` 内会回落默认值并给出告警）、`aspect_ratio`（仅文生视频，`16:9`/`9:16`/`1:1`）、`negative_prompt`、`enable_audio`。**这八个以外的字段一律 `INVALID_ARGS`**：`size`（生图那边才有的）、`ratio`、`n`、`return_base64` 这类从别的生图工具串进来的写法会在发请求前就被点名拒掉，而不是静默忽略让模型以为横竖版生效了——视频按次扣积分，一次几十秒，错一次代价不小。**默认不开启**、逐区勾选「允许模型自主生视频」，不勾时工具**根本不注册**；失败后 60 秒冷却，但参数错、没登录、读不到输入图、以及**上游在建任务之前就退回的 4xx**（它明说没扣积分）这类**一分钱没花**的失败不进冷却——改完参数可以立刻重试，不用白等一分钟；上游若在拒绝文案里报了时长区间（`supported range: 4-15 seconds`），插件会记住它，下次同样的越界值直接在本地拦下。**模型可按模式钉住**：卡片「能力」栏在视频开关下方按文生 / 图生各给一行选择框，写进 `preferredVideoModels`（按区、按标签存）；它是**软约束**——显式 `model` 写错照旧报错，钉住的模型若已从目录里消失则静默回落到组内第一个。两个区的模型目录不同（国内区 `kling-video-v3` / `minimax-video-h3`，国际区 `kling-video-v3`），id 不跨区。**实测单价（国内区）**：图生视频 4 秒 57.14（`minimax-video-h3`）/ 68.57（`kling-video-v3`），文生视频 5 秒 71.43 / 128.57 积分；**产物实测**是 H.264 + AAC、24fps 的 `1280x720` 或 `1344x768`（没有 1080p，`resolution: "1080p"` 会被拒并回落默认），视频码率 3.7–11.5 Mbps，秒数以 24fps 帧数为准（请求 5 秒得 5.09–5.17 秒）。取证、协议与联调记录见 [docs/VIDEO_GEN.md](../../docs/VIDEO_GEN.md)。

- **本机账号切换** —— 自动发现 WorkBuddy 桌面端留下的多个登录凭据，可按区域切换账号；Token 不写入 DSH 设置。
- **对话输入框积分读数（国内版 / 国际版自动切换）** —— 对话输入框左侧工具栏常驻一行可点击的读数（如 `WB CN · 1,072`），**按本会话当前选中的模型自动切换区域**：选中 WB CN 的模型就显示国内版余额，选中 WB AI 的模型就显示国际版余额；用其它 provider 的模型时该读数完全不出现。每 5 分钟自动刷新，也可点开手动刷新。点击读数弹出面板：**按账号列出的余额表格**，点某一行即可切换到该账号（与卡片上的账号选择是同一个设置）；**当前不能用的账号会在行内标出原因**（如「被限流」「积分耗尽」），标注口径与账号池表格一致。面板里的余额只在打开时才去查，因此不会让 5 分钟的后台刷新按账号数翻倍。要关掉某一边，就在卡片对应区域的 tab 下取消勾选「在输入框工具栏显示积分读数」；该区域的供应商被关闭时，读数不显示、开关也置灰。同一个开关下面还有「显示位置」这一行：默认在输入框工具栏（与模型选择同一行，位于模型选择器左侧、与权限切换器隔开），改成「输入框下方」后读数落到轮次/步数/token 统计那一行——装了别的插件把工具栏座位占掉时用得上。

- **账号池：多账号批量操作与自动换号** —— 把要用的账号勾进池子，即可**签到勾选的账号**、**测试勾选的账号 × 你指定的模型**（默认挑该区域倍率为 0 的免费模型）；开启**启用账号池**即同时打开**自动换号**——某个请求在上游失败时，插件会依次用池内其他可用账号重试，直到有一个接手、或全部不可用为止，然后才把错误报给你。成员**默认一个都不含**、必须显式勾选（「本机有登录」不等于「要拿它去签到和花积分」）；**开启后由池子的排序决定每一次请求用谁**（可用优先，其次快过期先花、积分高、凭据更新的）；失败时依次用池内其他可用账号重试。排序**从不写回你保存的选择**——关掉开关，你选定的账号立刻完全生效。只有请求本身不合法（HTTP 400）不换号：同一个请求体换谁都是 400，重试只会白等。**这个开关只管「插件要不要自己决定」**：关掉它，插件不再替你选账号、也不再替你换号，但**签到与测试仍然可用**。测试走的是与模型行同一套真实体积探测，因此**有真实成本**；签到会真实领取奖励，因此**默认只在你点按钮时执行**——另有一个**默认关闭**的「每天自动签到」开关，打开后插件才在后台替你领取（先读状态、已签的不重复领取，漏一天会断连签）。详见[账号池](06-账号池.md#账号池)。
- **企业版 / 教育版账号：签到与「领取」不适用** —— 带 `enterpriseId` 的席位（企业版或教育版）在池子里**不显示签到列、不显示福利活动，也不会发出领取请求**（5.8.0，issue #129）：上游对这类成员的个人权益**写**接口一律拒绝（实测 `10001`），而它的**读**接口照样把活动列出来、标着「未领」——所以「读到了」绝不能当成「可以领」。积分也在另一本账上（企业用量 = 上限 − 已用），个人积分表对这种账号返回空列表。这个判断贯穿池卡片、输入框胶囊与 Web 状态页，并且在账号进入池子的那一刻就带上标记，而不是等用户点了按钮才发现不支持。
- **可选：让上游用量页把这笔记成官方客户端发的那笔（5.8.0，issue #132，默认关闭）** —— 开 `usageIdentity` 后 chat 请求带上 `X-IDE-Name: WorkBuddy`（连同 `X-IDE-Type: CLI` 与版本号；版本号取自现有的产品 UA，不留第二个硬编码数字），用量页的「使用端」由此不再空白；会话身份三件套同时改成官方客户端那种 **32 位十六进制 UUIDv7** 并补上 `X-Request-ID`——网关把这个 id 回显成 SSE 的 `id` 并写进用量页，此前带连字符的 v4 与官方记录摆在同一页上像两种客户端；**每请求现生成、互不相同**这条没有放松。**`User-Agent` 在两种取值下都一字未动**——账单与限流认的是 CLI 通道；生图路径也不跟着这个开关变，它保持自己 2026-10-21 实测过的形状。**默认关**的理由：形状本身不修任何东西（`11128` 的三道门读的是消息开头、会话 id 有没有、首条是不是 system，头改不动其中任何一条），而实测证据来自报告者的账号与旧版本、本插件未在真机复现——一次纯显示对齐不该让所有账号先承担风险。另有可选的 `keepPromptLast`（**默认关闭**）：用量页的「请求」列取自 body 里**最后一条** `user` 消息，而宿主把时间采样、运行时上下文、`<system-reminder>` 追加在你真正输入的那句**之后**，那一列于是常年记的是注入块；开启后把这些注入块**搬到真实输入之前**（只变顺序；另外会剥掉**被记录那一条**真实输入前面的 `<acp …>mNNNNN</acp>` 标记，否则那一列仍然以标记开头而等于没修，更早的消息一律保留自己的标记，因为模型靠它们引用历史）。默认关的理由是它会改变上游会数到的消息顺序、并删掉真实输入的几个前导字符；搬移只匹配宿主自己的注入前缀，而普通对话在没有注入尾块时逐字节不变（连标记也不剥）——这两点各有专门测试钉住。
- **可选：把每个新会话的标题请求改到隐藏轻量模型（issue #133，默认关闭）** —— DSH 宿主每个新会话会发一次标题生成请求，走的是与对话相同的 provider，于是这笔按主付费模型的费率计费。开启 `sessionTitle.enabled` 后，插件把能按宿主标题模板（`Generate the session title from this JSON array of human messages:` 开头、整条 body 只有这一条 user 消息）识别出的标题请求改写到 `sessionTitle.model`（默认 `wb-lite`）。报告者实测该模型对这类请求 **0 积分**，但注意三点：这仍是**真实上游请求**，请求数照算；证据是报告者账号级的，本插件未复现；识别按 fail-closed 设计——宿主若改模板，改写静默停止、回到原计费，不会误伤普通对话。若上游拒绝该模型，只是该会话标题生成失败一次，不影响主对话。另外，`sessionTitle` 与本条及上一条的 `usageIdentity` / `keepPromptLast` / `extraInjectedPrefixes` 一样，都是插件挂载时读一次配置：**改完 `cordis.patch.yml` 后需要重载插件或重启 DSH 才生效**，热改不生效。
- **福利活动：待领取标记 + 单账号「领取」按钮** —— 卡片会逐账号标出上游活动（补偿 / 赠礼）里**还没领的那一份**，数据来自上游自己的两个状态接口，标记阶段**只读**、两个写接口一次都不调用。显示规则完全由上游状态决定：`active && !claimed` 才显示，`claimed` 整行消失，活动过期（`active` 翻 `false`）自动消失——**不用本地时钟去比 `end_time`**，本机时间偏了也不会与服务端打架；`end_time` 只用于 3 天内临期高亮。`active` 单独看不行：已领取的账号 `active` 仍为 `true`，只看它会让领过的账号永远挂着待领取。读取复用签到的管线（每账号一次、30 分钟缓存、账号池关闭时不发请求），任一接口失败按「未读」处理，不会把一次失败缓存成「全都没福利」。行尾是一个实心琥珀色的**胶囊按钮「领取」**，一次只领**一个账号的一个活动**：没有「全部领取」，因为一次点击花掉的是一份不可撤销的真实权益，写路由也**强制要求 `accountId`**，请求本身无法批量领取。领取前**重新读取**状态再判定，已领取或已过期一律 409 且不调用上游；领取后用上游的**新读数**作答并刷新卡片，不做乐观更新——即使上游静默失败也不会留下「已领取」的假象，成功后同时清掉该账号的福利缓存，按钮不会顶着旧状态赖着不走。
- **可选：被网关渠道校验拦截后的最后兜底「继续」（默认关闭，默认只发 1 次）** —— 上游用 `400` + 业务码 `11128` 拒绝时，这一轮就此结束：插件不会在原请求里重试（三级救援已跑完），不会换号（网关匹配的是消息内容，每个账号发出去都一样），宿主也不重试。**它不是 11128 的修复**：固定 system 指纹（#163 的 identity / Web GUI / @ 路径整段）每一轮逐字节相同，重发只会再付一次同一个 400；5.13.1 起这些由 `prepareChatBody` 的按句改词处理（5.14.0 又补上 Web GUI 段落的第二句，见 #167）。只有被拒内容刚好随轮次变化的窄情况，才可能靠新回合碰过去。开启卡片「能力」栏的开关后，插件检测到这一类失败、等 300ms、用 `agent.followup` 发一条 `继续`（`source.kind` 是 `workbuddy-continue`，**不是** `user`）。**上限数的是「连续」次数**（`channelRejectContinue.maxConsecutive`，默认 **1**；旧默认 3 已证伪——1 次救不了，3 次也救不了）：成功一轮、或你自己发一条消息，计数清零；插件自己发的不清零。子代理会话一律不碰；会话正在跑、或收件箱已有排队内容时也不发。**每次都会真实消耗一次请求**，所以默认关闭；它也是本插件里**唯一一个改完即生效**的上游类开关。与其它上游开关一样，也能直接在 `cordis.patch.yml` 里写：

  ```yaml
  channelRejectContinue:
    enabled: true
    maxConsecutive: 1
    text: 继续
  ```

- **凭据失效时给出可执行的建议** —— 上游拒绝当前账号的 token 时，插件会**实际探测**本机其他账号：若有账号仍然可用，就直接告诉你「切换到它即可」（并附一键切换），而不是笼统地让你重新登录——被钉在一个作废的旧备份上时，重新登录并不能解决问题。只有本机确实没有别的账号可切换时，才会提示重新登录。
- **扫码添加账号、批量导入导出、逐账号测试/删除** —— 不必先装 WorkBuddy 桌面 App：卡片里的「扫码登录」按钮（国际版为「网页登录」——那边是浏览器登录页，没有二维码；这一行就在「更多设置」上方，点一下立即生效，不需要保存）点开即弹出对话框，并在浏览器里**自动打开**授权页；被浏览器拦截时对话框内提供链接、复制与「重新打开页面」兜底。所有凭据统一落到插件自己的凭据库（`$DSH_HOME/workbuddy-vault/<region>/<accountId>.json`，一账号一文件），**桌面 App 的认证文件始终只读、永不被改动**。账号表格每一行右侧有「测试」与「删除」：测试与批量测试走同一套探测，结果可比；删除只删插件自己存的那份，并把这个账号**暂时隐藏**：删掉后立刻消失，也不会被自动轮询带回来；点「重新检测账号」即可找回（重新登录或导入同一账号也会清除隐藏记录）。**桌面 App 的登录始终不动**——删除是「本插件不再列出它」，不是退出 App 登录。「导出 / 导入账号」可把凭据搬到另一台机器：多选导出 JSON → 选文件后先看**脱敏预览**（只显示字段与是否有 token，明文不进预览）→ 勾选导入。导入按账号去重覆盖，**只有确认属于该区域**的记录才入库，认不出的域名会被跳过并如实计入「已跳过」。详见[账号池](06-账号池.md#账号池)。
- **积分信息在账号池里** —— 成员表逐账号显示剩余积分与最近到期时间，排序的第二键就是积分（谁多谁优先）。查询是**只读**的、不消耗积分。
- **凭据路径多候选** —— macOS / Windows / Linux 逐一探测默认位置，也支持环境变量与卡片内直接指定。**未登录时卡片会列出「探测过哪些路径、各自为什么没成」**：五档原因（不存在 / 读不了 / 没有可用 token / 字段已加密且拿不到密钥 / 属于另一个地区）分开呈现，因此「已经登录了、但桌面 App 不在场」这种最容易误判的情况会明说需要 App 在场，而不是叫你重新登录一次。**属于另一个地区**那一档尤其不同：登录信息是真实可用的，只是挂在另一个标签页下，卡片会直接给出结论「切换标签页即可，不用重新登录」。列表只讲一次——提示段落说结论，折叠列表给路径细节，两处不重复同一件事。
- **安全 loopback shim** —— 每区域一个随机端口 + 进程内随机 secret，真实 WorkBuddy token 不交给 pi-ai。
- **命令行诊断** —— `status` / `doctor` / `logout`，按区域报告登录与积分，无需浏览器即可确认宿主状态。
- **CLI 路线（可选，默认关闭）** —— 伪装成 CodeBuddy 客户端过渠道校验是一条军备竞赛的路，而且已经出现账号级限制（issue #98 的 code 11140）。另有一条路不做这层伪装：让**本机已登录的 CodeBuddy CLI 自己跑任务**，由它去读文件、跑 git、改代码。打开 `cliBridge.enabled` 后插件多出 `codebuddy_ask` 工具和 `/codebuddy` 指令，跑完把结论回注给会话模型。关闭时插件行为与之前**完全一致**。**它绕开的是客户端指纹层，不是账号层**：用的仍是本插件 vault 里的同一批账号，所以不该把它当成「封号之后的免死金牌」。详见 [CLI 路线](10-CLI路线.md#cli-路线可选让-codebuddy-直接干活)。
- **WorkBuddy 联网搜索（可选，默认关闭）** —— 让 DSH 内置的 `web_search` 用本插件登录的 WorkBuddy 账号去搜，而不是 DeepSeek 搜索。默认约 1 秒返回结构化摘要；可选综述模式返回带引用的长答案（慢，10–60 秒）。**不修改宿主的搜索提供方设置、不依赖任何其他插件**——注册成一个独立 provider，由你在设置的网页搜索下拉框里自选。详见 [WorkBuddy 联网搜索](03-联网搜索.md#workbuddy-联网搜索可选)。
