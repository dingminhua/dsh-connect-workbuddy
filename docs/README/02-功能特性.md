## 功能特性
配置入口统一在「设置 → WorkBuddy」：左侧导航的一页，顶部是国内版 / 国际版两个 tab，各含独立的账号池与模型管理；5.19.0 起插件市场的 bundle 详情页不再显示配置卡片，
同一份配置只留这一个编辑入口。
### 界面与供应商
**双供应商并行。** 国内版注册为 `workbuddy`（GLM-5.3、DeepSeek-V4-Pro、Kimi-K3、MiniMax-M3、Hy3 等），国际版为 `workbuddy-global`（GPT-5.6、
Gemini-3.5-Flash、GLM-5.3、Kimi-K3 等）。有账号的区域其模型才出现在 DSH 选择器里；两边都有账号时两组同时可选、互不干扰。**本机没有账号的区域不列出任何模型**；在该区域登录一次后「重新检测账号」
或重启即出现。provider 始终注册着——它的设置页就是登录入口。
  - 模型名内嵌上游积分倍率（如 `GLM-5.3 · x0.79`），与 WorkBuddy 自身菜单一致；活动时段显示折后价（如夜间折扣时变 `x0.06`），活动结束自动还原，无需重启。
  - **tab 隔离**：每个 tab 的账号、目录、勾选与未保存草稿完全隔离——在一个 tab 切账号或刷新模型，不会触碰另一边。
  - **可单独关闭任一供应商**：每个 tab 右侧勾选框默认都开；取消勾选即把该供应商从选择器和「设置 → 模型」目录里彻底撤掉，启动时也不再为它发请求。账号、积分、目录与勾选全部保留，重新勾选即完整恢复。
  若某会话此前选中的正是被关闭供应商的模型，再调用会报 `NO_ADAPTER`，卡片会提示，不会静默失败。
**设置页分四栏：账号 / 模型 / 能力 / 诊断。** 账号改动点一下即生效；模型目录改动是草稿、必须点保存。切栏不会重新拉取，也不会丢掉未保存的目录草稿（非活动栏用 `hidden` 隐藏，不进无障碍树）。
「能力」栏放授权类开关（CLI、生图、积分读数位置），点一下即生效、不过保存，且各留有子选项位置。「诊断」是只读事实表——区域、上游域名、服务账号、登录有效期、目录模型数/启用数、账号池开关、上游最近一次错误原文（原样引用）
——专为整段贴进问题反馈而设，没有任何会改设置的控件。
**侧边栏入口（`sidebarPanel`，默认关闭）。** 勾选后在 DSH 侧边栏加一行 WorkBuddy，点开是这张卡片的整页版（左上有「返回会话」）。默认关闭因为它占的是所有插件共用的全局侧边栏座位，
而「设置 → WorkBuddy」本就能打开同一页。开关在「能力」栏，勾上即出现、取消即消失，不走保存。关掉时是注销注册（不是渲染空组件）：侧边栏行由槽位元数据拼成，返回 `null` 只会得到空白但可点的按钮，
所以决策点在 `apply`（`src/client/panel-switch.ts`），关掉即 `dispose`。首屏状态问宿主（usage 文档的 `sidebarPanelEnabled`），
不问浏览器里的设置镜像——后者在部分 0.1.7 上是陈的且值变化时不更新。开着面板时关掉，中间栏自己回对话，无需插件导航。macOS 实测见 [MAC-VERIFY-PR188-REPORT.md](../../docs/MAC-VERIFY-PR188-REPORT.md)，
验证清单见 [MAC-VERIFY-PR188.md](../../docs/MAC-VERIFY-PR188.md)。
**刷新频率（`pollIntervalMs`，默认 5 分钟）。** 每次刷新要为池内每个账号各读一次积分和一次签到状态——4 个账号按旧的固定 60 秒算约 11,520 请求/天，而这些数字变化很慢，
故默认改为 5 分钟。「能力」栏给五档（1/5/10/30/60 分钟），点一下即生效、不走保存；输入框的账号面板跟随同一个值，改一处两处一起变。取值是封闭五档，配置文件里手写的 `0` 等一律回落默认值。
### 模型目录
**模型管理。** 从上游刷新完整目录，逐项勾选启用/禁用——**勾选是草稿，点保存才生效**。但目录与倍率随刷新即刻落盘生效（价格不属于草稿，否则卡片会继续显示旧价、`/usage` 各说一套）。你的勾选、
上下文预算、图片勾选与默认推理档仍只在保存时提交。
  - **默认推理强度选择器**（每模型一行）：请求未指定档位时用哪一档（新对话、压缩摘要、会话标题都属于这类）。选项来自该模型自己声明的档位（如 `deepseek`/`glm-5.3` 是 `low/high/max`，
  `glm-5.2` 是 `high/xhigh`），故只能逐模型选、不能全局一个值。第一项写明真正会用的档位——上游声明优先，否则取该模型的中档（不是最弱档，避免默认调低思考）。这一行取代了原来只读的「推理强度：
  …」。
  - **图片输入按核验表判定**：刷新时只有核验表收录为原生多模态的模型才自动勾选，写明纯文本的不勾，**没有资料的 id 按「未核实」不猜**（上游 `supportsImages` 是平台声明，
  不等于模型能看图，不参与判定）。核验表证据分厂商文档（13 条）与上游目录自述（2 条：`space-bunny`、`minimax-m3.1-flash`），新增 id 仍要求厂商来源，见 [DESIGN.md](../../docs/DESIGN.md)「图片输入」
  一节。用户可随时手动勾选，状态保存在本地。
  - **可关闭思考（`off`）勾选框**：决定是否为该模型提供「完全关闭思考」档位，默认由内置复核名单给出（9 个上游声称可关闭但实测返回 400 的模型默认不勾）。名单内那 9 个**不可勾选**（行上标「拒绝 off」）：
  勾上后 pi-ai 会把它当作所有未指定档位请求的默认值，压缩摘要正属此类，等于让每次 `/compact` 都 400 / 11133。名单外的模型由你的勾选与自身声明决定，首次保存写入后不再重算。
**活动徽标。** 上游目录自带活动信息（免费试用、夜间折扣、限时免费、订阅优先等），插件复用刷新目录时已拉的那份配置、**不新增请求**，直接在模型行画胶囊徽标，颜色文案由上游给出，悬停看活动说明、
起止日期与每日时段。徽标是「此刻」的函数：只在声明的时间窗内显示，多条命中只画优先级最高的，没给结束时间的权益标记常驻。徽标只是提示，不改变模型行为。同一枚徽标也出现在 DSH 模型选择器里（菜单行用短词「夜间」
「限免」，触发器用完整词），判定用同一份数据、同一个时钟。取证与判定规则见 [PROMO_BADGE.md](../../docs/PROMO_BADGE.md)。
**繁忙程度（仅国内版）。** 上游只读探针 `POST /v2/chat/busy`（一次最多 50 个 id，免费）回答模型此刻多忙，画成模型名旁的小人图标：排队人数 = 小人个数（1 黄 / 2 橙 / 3 红），
空闲是绿色小火箭，不可用是划掉的小人。`unknown` 一律不画——「没被告知」不当成「一切正常」。等级不落盘，只盖在运行时目录上随进程消失；探针失败只记 warn，不挡目录刷新。**国际版没有此徽标**：
国际网关根本没有这条接口（`/v2/chat/busy` 等路径全 404，`/v3/config` 也无负载字段），这是上游从未提供该数据，探针失败后安静退化成「没有徽标」。
**排队位次。** 撞上排队业务码（`6020` 等待、`6021` 队列满、`6022` 已达上限）时，插件给出「你排在第 N 位，队列共 M 个请求，请稍后重发或换模型」。排队不触发换号（队列跟随模型与平台，
换账号位次相同），也不自动重发/重试（`x-should-retry: false`）——几千位之后重试十几次也轮不到，只会白烧请求。位次报出来由你决定。
**模型可用性测试。** 每个模型行的「测试」按钮告诉你此刻能否使用、不能用时何时恢复。它发**真实体积的请求（约 25k 输入 token）**，因为上游限流按请求体积触发，小请求看着正常、长对话里却可能被拒。
恢复时间从 429 **响应体**解析（`{"code":6004,"msg":"…将在 <时间> 重置…"}`，按声明的 UTC 偏移换算，不受本机时区影响）；三处来源都没说时如实显示「上游未给出何时恢复」，
不编造倒计时，也不借用月周期刷新时间。成功即无冷却（200 响应带的 `Retry-After` 是月度积分包刷新时刻，不是禁用时间）。探测在后台发起、凭据不传到页面、结果不写入设置也不改勾选。
两点须知：① **它真的花钱**（实测一次约 `credit` 0.02，被限时几乎不花），所以只能单个模型手工点，服务端也只接受单个模型。② 上游宣称 1M 上下文但节流线远低于此；插件按模型**原生窗口**向 DSH 宣称，
想更早压缩就在模型行手动设「DSH 上下文预算」（200K / 500K / 原生窗口）；「原生窗口」档表示**没有上限**（删掉预算条目），这样上游日后调大窗口时该档会跟着变大。
### 生成工具（默认关闭，逐区授权）
两者都**默认不开启**——这是插件里仅有的「由模型自己决定花钱」的能力，宿主没有调用前确认机制。不勾时工具根本不注册，模型看不到也不会发起注定失败的调用。勾选是逐区的，两区都开时优先国内区；失败后有冷却（不扣费的失败不进冷却，
可改完参数立刻重试）。价目、协议与联调记录见 [IMAGE_GEN.md](../../docs/IMAGE_GEN.md) / [VIDEO_GEN.md](../../docs/VIDEO_GEN.md)。
**生图 `workbuddy_draw_image`。** 国内区 `hunyuan-image-alpha`（约 5.71 积分/张）、国际区 `hy-image-3.5`（约 0.03 积分/张），
积分池彼此独立，5.71 与 0.03 不是同一张图的跨区差价、别做汇率换算。请求体照抄官方 CLI 的 ImageService（`POST /v2/images/generations`），产物是 24 小时有效的 COS 签名 URL，
会提醒及时下载。
  - **文生图 / 改图由「有没有图」唯一决定，没有 `mode` 参数。** 给 `image` 参数（**字符串数组**，本地路径 / `file://` / `http(s)` / data URL / 裸 base64，
  单张也要写成 `["/abs/a.png"]`，上限 8 MB）就切到 `POST /v2/images/edits` 并用 image-to-image 模型（国内 `hunyuan-image-alpha-edit`、
  国际 `hy-image-3.5`）；输入图只归一成 data URL，不缩放/裁剪/转格式。
  - **`size` 必填**，写「宽x高」或 `auto`。合法范围两边各 512–2560 像素、面积不超约 419 万；越界会等比缩放后照常出图并在 `hint` 说明（`4K` 超出上限，
  横竖方分别与 `2K` 同档，顶格是 `2048x2048`）。改图推荐 `size: "auto"`：工具从图片字节解出宽高给同比例画布，模型不必猜。改图若写具体比例，裁切/留白要在调用前说明并等同意（不可逆，
  不能与价格可逆的事共用一句话）。
  - 工具描述按「具体像素 → 比例词 → 档位词 → 改图 auto → 用途 → 表外比例 → 只提方向 → 默认档」八阶顺序命中即停；表外比例给算式（长边尽量 2560，超面积按比例缩），「只提方向」
  统一给横/竖/方常用档。
  - 真实扣费以返回的 `credit` 为准，结果写明走哪个区、用的模型、扣了多少；描述里不点名具体模型 id，`model` 一般留空最稳。参数错、没登录、模型不存在不扣费、不进冷却。工具定义是手写 raw JSON Schema，
  **没引入新依赖**。
**生视频 `workbuddy_draw_video`。** 视频是**异步任务**：`POST /v2/videos/generations` 回 `taskId`，再轮询 `POST /v2/videos/tasks` 至 `completed`（5 秒一次、
上限 10 分钟），产物下载到 `os.tmpdir()/workbuddy-video-gen/`，只回 `file://` 本地路径（不塞进对话体）。
  - 文生 / 图生同样由 `image` 有无决定（**只收一张**，与生图的多张不同）。参数：`seconds`（默认 5，须在模型 `[min,max]` 内）、`resolution`（不在模型列表内回落默认并告警）、
  `aspect_ratio`（仅文生）、`negative_prompt`、`enable_audio`；这八个以外的字段一律 `INVALID_ARGS`（视频按次扣费，错一次代价不小）。
  - 失败后 60 秒冷却，但参数错、没登录、读不到图、上游建任务前就退回的 4xx（明说没扣费）不进冷却；上游若在拒绝文案里报时长区间会记住并在本地拦下越界值。模型可按模式钉住（`preferredVideoModels`，
  按区按标签存，软约束，钉住的模型消失则回落组内第一个）。
  - 两区模型目录不同（国内 `kling-video-v3` / `minimax-video-h3`，国际 `kling-video-v3`），id 不跨区。实测（国内）：图生视频 4 秒约 57–69 积分，
  文生 5 秒约 71–129 积分；产物是 H.264 + AAC、24fps 的 `1280x720` / `1344x768`（无 1080p）。
### 账号与积分
**账号池。** 把要用的账号勾进池子，即可批量签到 / 测试（默认挑该区倍率为 0 的免费模型）；开启「启用账号池」即同时打开自动换号——请求失败时依次用池内其他可用账号重试。成员**默认空**、必须显式勾选（「本机有登录」
不等于「要拿它去签到和花积分」）。开启后由排序决定谁服务（可用优先 → 快过期先花 → 积分高 → 凭据新），排序**从不写回你保存的选择**，关掉开关你选的账号立刻生效。只有请求本身不合法（HTTP 400）
不换号。**这个开关只管「插件要不要自己决定」**：关掉它插件不再替你选/换号，但签到与测试仍可用。测试走真实体积探测、有真实成本；签到真实领取奖励、默认只在你点按钮时执行（另有默认关闭的「每天自动签到」）。
详见[账号池](06-账号池.md#账号池)。
**扫码登录与凭据管理。** 不必先装桌面 App：卡片里的「扫码登录」按钮（国际版是「网页登录」，浏览器登录页）点开弹出对话框并自动打开授权页，被拦截时有链接、复制与「重新打开页面」兜底；这一行在「更多设置」
上方，点一下立即生效。凭据统一落到插件自己的凭据库（`$DSH_HOME/workbuddy-vault/<region>/<accountId>.json`，一账号一文件），**桌面 App 的认证文件始终只读、永不改动**。
每行右侧有「测试」「删除」：删除只删插件存的那份并暂时隐藏该账号，点「重新检测账号」找回（重新登录或导入同一账号也会清除隐藏记录），桌面 App 的登录始终不动。「导出 / 导入账号」可搬到其他机器：
导出 JSON → 先看**脱敏预览**（明文不进预览）→ 勾选导入；按账号去重覆盖，只入库确认属于该区的记录，认不出的域名跳过并计入「已跳过」。详见[账号池](06-账号池.md#账号池)。
**对话输入框积分读数。** 输入框左侧常驻可点击读数（如 `WB CN · 1,072`），**按本会话当前选中的模型自动切区**；用其它 provider 的模型时不显示。每 5 分钟自动刷新，点开弹出按账号的余额表格，
点行即可切换账号；不可用账号行内标出原因（口径与账号池一致）。面板余额只在打开时查，不会让后台刷新按账号数翻倍。可在对应 tab 关掉该读数；「显示位置」可改为「输入框下方」。
**积分在账号池里。** 成员表逐账号显示剩余积分与最近到期时间，排序第二键就是积分；查询只读、不消耗积分。
### 可选接入
**CLI 路线（`cliBridge.enabled`，默认关闭）。** 让本机已登录的 CodeBuddy CLI 自己跑任务（读文件、跑 git、改代码），插件多出 `codebuddy_ask` 工具和 `/codebuddy` 指令，
结论回注给会话模型；关闭时行为与之前完全一致。它绕开的是**客户端指纹层，不是账号层**——用的仍是同一批 vault 账号，账号级限制（如 `11140`）照样生效，不是「封号免死金牌」。详见[CLI 路线](10-CLI路线.md#cli-路线可选让-codebuddy-直接干活)。
**WorkBuddy 联网搜索（`webSearch.enabled`，默认关闭）。** 让 DSH 内置 `web_search` 用本插件登录态去搜，约 1 秒返回结构化摘要；可选综述模式（带引用、
10–60 秒、吃积分）。不修改宿主搜索提供方设置、不依赖其他插件——注册成独立 provider，你在网页搜索下拉框里自选。详见[联网搜索](03-联网搜索.md#workbuddy-联网搜索可选)。
### 其它细节
  - **企业版 / 教育版账号**：带 `enterpriseId` 的席位是个人权益写接口的拒绝对象，池子里不显示签到列与福利活动、不发领取请求；积分在另一本账上（企业用量 = 上限 − 已用）。
  - **福利活动**：逐账号标出上游活动里未领的那一份，标记阶段只读。显示完全由上游状态决定（`active && !claimed`），不靠本地时钟比时间。领取是一次一个账号一个活动、领取前重读状态、
  成功后用新读数作答——没有「全部领取」，因为一份权益不可撤销。
  - `usageIdentity`（默认关闭）：chat 请求带官方客户端身份头，让上游用量页记上使用端；`keepPromptLast`（默认关闭）：把宿主注入块搬到真实输入之前，修正用量页「请求」
  列常年记成注入块的问题。两者都默认关，理由是不该让所有账号先承担纯显示对齐的风险。
  - `sessionTitle.enabled`（默认关闭）：识别宿主的新会话标题请求并改写到隐藏轻量模型（默认 `wb-lite`，报告者实测 0 积分）。识别按 fail-closed 设计，
  宿主改模板则静默停止。上述插件挂载时读一次配置，改 `cordis.patch.yml` 后需重载插件或重启 DSH。
  - **渠道校验兜底「继续」（`channelRejectContinue`，默认关闭，最多连续 1 次）**：只在网关 `11128` 拒绝后用 `agent.followup` 发一条「继续」；
  它不是 11128 的修复，只对内容随轮次变化的窄情况可能有效，每次真实消耗一次请求。
  - **凭据失效时给出可执行建议**：实际探测本机其他账号，有可用的直接告诉「切换即可」并附一键切换，而不是笼统叫你重新登录。
