## 反向代理 / 局域网访问（issue #261）
把 DSH 装在 Docker / 服务器上、前面再挂一层 Caddy、nginx 之类的反向代理时，插件的设置卡片可能整块空白、`/plugins/dsh-connect-workbuddy/*` 全部返回 `403 {"error":"host-not-trusted"}`——**而 DSH 自己的页面和设置是好的**。
这不是登录问题，重新登录 WorkBuddy 改不了它。
原因是卡片路由的 Host/Origin 闸门：它要求请求的 `Host` 等于连接实际落到的本机地址（`req.socket.localAddress`）。反代后面 DSH 绑定的是回环地址，这个值永远是 `127.0.0.1`；
而代理默认**原样转发**浏览器发来的 `Host: <对外地址>`，两者永远不相等，于是闸门全部拒绝。DSH 自己的 `/api` 另有一套栅栏，用 `dsh web --trusted-host <地址>` 声明的 authority 放行同一个 Host，
所以「页面能用、插件坏了」。
修法：在插件配置里加一个 `trustedHosts`，把对外地址（与宿主的 `--trusted-host` 同一个 authority）声明进去：
```yaml
# profile 的 cordis.patch.yml，或插件设置里对应字段
trustedHosts:
  - 192.168.1.250:8443      # 带端口：只放行这一个 authority
  # - dsh.example.com        # 不带端口：该主机名任意端口都放行
```
  - **默认空**，本地回环 / 直接绑 LAN 地址的部署行为完全不变。
  - 元素必须是裸 `host[:port]`，不能带路径、协议、用户名；写错会在插件加载时报错，而不是悄悄放行一个前缀。
  - 它是 **volatile** 字段：加完立即生效，不需要重载插件或重启 DSH。Host 与 Origin 两道闸门读的是同一份列表，不会出现「Host 放行、Origin 又拦」。
  - 这**不是鉴权**：Host/Origin 本就可伪造，白名单只是把「本机地址」的定义从「socket 落在哪」扩展到「部署方声明的权威」，与 DSH 主程序对齐。DNS rebinding 防护不变——攻击者页面的域名不在列表里，
  照样被拒；`0.0.0.0` / `[::]` 仍显式拒绝。
如果不想配它，最简单的办法是**用 DSH 的本机地址（`127.0.0.1`）打开页面**，而不是对外地址或反代地址。修好后卡片会直接显示账号与积分；在修好之前，卡片会给出一条明确的 403 提示，
不再让你去「重新登录」。
