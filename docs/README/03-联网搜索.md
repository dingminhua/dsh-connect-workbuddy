## WorkBuddy 联网搜索（可选）
DSH 的 `web_search` 工具由宿主提供，实际检索走一个可替换的「搜索提供方」。本插件可以注册一个用**自己登录态**的提供方（issue #332），但**默认完全不启用、也不改你的任何设置**：
   1. 在插件设置的**能力**页勾选「让 DSH 网页搜索走 WorkBuddy」（即 `webSearch.enabled`，默认 `false`）。
   2. 打开的同时，插件会把宿主 **网页搜索提供方**自动切到「WorkBuddy（本插件登录态）」（id `dsh-connect-workbuddy-search`），立即生效；关掉时自动恢复你原来的设置，
   不会留下失效的提供方。你也可以随时到 **插件 → 内置插件配置 → 网页搜索与获取** 手动改回别的提供方。
配置字段：
| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `webSearch.enabled` | `false` | 是否注册这个搜索提供方，并自动把宿主的搜索提供方切到它（关闭时恢复原值） |
| `webSearch.agentic` | `false` | `false` 走快路径（约 1 秒的结构化摘要）；`true` 走综述路径（带引用、10–60 秒、吃积分） |
| `webSearch.maxContentChars` | `30000` | 综述回传上限字符，`0` 不截断 |
行为与边界：
  - **按当前账号检索**：搜索按发起请求的模型路由选区（`workbuddy` → 国内版、`workbuddy-global` → 国际版），用该区**当前选中的账号**。token 失效时用本插件已有的刷新链在内存续期，
  不写桌面 App 的认证文件。
  - **零冲突**：provider id 独立，不顶替内置的 `deepseek-official` / `deepseek-search-api`，也不写死 patch；对宿主 `searchProvider` 的改动由开关驱动、
  关闭即恢复。即使你装了别的搜索插件，也各自独立；关闭开关或正常卸载会恢复宿主设置。（进程被强制终止来不及清理时，下次启动开关为关会自动收回残留指向。）
  - **未登录会报错而非静默降级**：本提供方的 `available()` 恒为 true（它不预判登录态），桌面端登出时由搜索请求本身报错（如 `WB_SEARCH_SESSION_DEAD`），
  不会偷偷改走 DeepSeek。想换回官方搜索，关掉开关（会自动恢复宿主原设置）或在下拉框切回去即可。
  - **只管搜索不管抓取**：`web_fetch` 仍是宿主自己的抓取后端，与本功能无关。
  - 这是 WorkBuddy 桌面 App 内部使用的非官方接口，可能随版本变化；属于可选增强，不是核心聊天能力。
