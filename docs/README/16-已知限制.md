## 已知限制

下面按接口凭据、平台写入、错误码、跨区域上下文分组。

### 接口与凭据

**依赖非官方接口。** 插件使用 WorkBuddy 客户端自身的接口，不是开放 API；上游更新后插件可能需要随之调整。

**账号切换基于历史 auth 文件。** 凭据来自桌面端留下的备份产物，不是官方多账号 API；默认跟随 App 当前登录，切换账号是显式选项。

- 保存的账号若在本机消失（App 换登录或清理备份），插件**不会**静默改用别的账号——那样账单会落到另一个账号上。卡片会提示「保存的账号已不存在」，重新选一个账号、或点「跟随 App 当前登录」
  清除选择即可恢复。**重新登录桌面端修不了这种状态**：凭据本身是好的，失效的只是保存下来的账号标识。
- 从 2.0.0 前升级的用户可能残留旧版顶层 `accountId`：它只作用于所属区域，且该区域被显式清除（`accounts.<区域> = ""`）后才彻底不生效。卡片会标明每个区域是「使用保存的账号」
  还是「跟随 App 当前登录」——清除后回到的默认账号往往与刚清掉的相同，靠这行提示才能分辨清除是否生效。

**加密凭据需要桌面 App 在场。** 5.6.0 起（macOS 与 Windows 相同）auth 文件里的 token 被加密，插件需调用 App 自身的原生绑定取回字段密钥。

- App 未安装、被卸载或装在探测路径之外时，加密文件读不出来，账号显示为**未登录**，不会退化成残缺 token；Windows 会自动回退查安装注册表，仍找不到时用 `WORKBUDDY_APP_EXECUTABLE` 指定。
  `doctor` 会报告这项能力是否可用。
- 密钥每次向本机 App 现取、不落盘，随 App 版本轮换；App 升级后无需升级插件。
- **「未登录」不等于「登录信息读不出来」**：后者不是重新登录能解决的。
- App 可执行文件按 bundle 声明的 `CFBundleExecutable` 定位（macOS 上是 `Electron`，不是 `WorkBuddy`），并核对 bundle id，不会误启动同名的其他 Electron 应用。

**凭据路径只在部分平台真机验证过。** Windows / Linux 按平台约定推导；已在 Windows 11 确认 `%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth` 与 `%LOCALAPPDATA%\Programs\WorkBuddy\WorkBuddy.exe` 命中，
其余候选与 Linux 路径仍未经真机逐项验证。不在默认位置时用 `WORKBUDDY_AUTH_FILE` 指定。

### 平台与写入

**Windows：配置文件被占用时账号改动可能保存失败。** 杀毒软件、OneDrive 或编辑器会短暂锁住 profile 的 `cordis.patch.yml`。插件写入后会回读校验——确认落盘才显示「已清除」，
失败则明确报错并保留原选择。遇到时关闭占用该文件的程序后重试。

**独立 CLI 不带宿主的 peer 包。** `dsh plugin … exec` 在宿主之外运行时回落到自带的原子写实现（`src/host-peers.ts`），只在宿主 peer 解析不到时启用；
宿主内和仓库检出里仍用宿主那份。`doctor` 会报告当前用的是哪一份。详见[命令行](11-命令行.md#命令行)的 issue #47 说明。

### 错误码辨认

很多「看起来像登录坏了」的报错其实不是登录问题，先对照下表：

| 现象 | 实际含义 | 怎么办 |
| --- | --- | --- |
| 403 `request illegal`（`11140`） | 服务端按内容策略拒绝，**不是登录问题**，重新登录无效 | 在桌面端用同一账号发同样内容验证；或换区域/账号重试。报错含官方文案、`code` 与 `requestId`（联系官方支持时提供） |
| `model_busy`（`14003`） | 模型级、暂时限流，与账号和积分无关 | 换一个模型即可；现按 `RATE_LIMIT` 进入有界的原地重试 |
| `soft_rate`（`6004`） | 真正的限流，重置在几小时后 | 仍记为 `quota_exceeded`，不进入重试集合（重试换不出答案） |
| 429 `Credits exhausted`（`14018`） | 真的额度不足（国际版选到付费孪生模型） | 见下方说明 |

- `11140` 写回宿主的 `error.code` 是稳定类别 `policy_reject`（不是数值 `11140`）：策略拒绝是确定性的，重试只会白烧预算，所以宿主不会原地重试。
- **国际版有两个「Deepseek-V4.1-Flash」。** `deepseek-v4.1-flash`（`x0.00`，免费）与 `deepseek-v4.1-flash-sg`（`x0.03`，
  付费）的名称、说明、能力字段逐字相同，选择器里只有乘数后缀能区分。零积分账号选到付费那个会得到 429 / `14018`，这时「额度已用尽」是**正确**的。国际版免费模型只有 `deepseek-v4.1-flash`、
  `hy3`、`step-5-preview` 三个。
- 宿主按错误**文本**正则分类（`401`/`403` → `AUTH`，`quota` 措辞 → `QUOTA`，`400` → `INVALID_REQUEST`），所以写回宿主的错误体不能随意带上这些字面量，
  否则会被替换成宿主的固定话术（如「当前请求的额度已用尽」——那句话从来不是插件写的）。

### 跨区域的上下文跳变

**现象。** 换区域后 token 计数可能跳 ±30%~94%，甚至本来不超限的会话一换区就撞 `code 11115 prompt is too long`。在同一个区域内换模型也可能看到计数变化。
跳多少只取决于另一侧 thinking 的字符数，与历史总长无关。

**根因。** 宿主内置的 pi-ai 重放历史时按 `isSameModel` 判断：provider、api、model id 三者不全等的消息，其 thinking 会被**降级成普通正文**（不是丢弃）
——正文是网关会计数的，thinking 走另一个字段。国内版与国际版是同一 model id 的两条 provider 路由（见[工作原理](04-工作原理.md#工作原理)），所以换一次区，另一侧产生的大量 thinking 就整批挪进正文桶。
这是宿主与 pi-ai 之间的错配，**不是本插件的 bug**。

**已修复的部分。** 4.9.2 起两条路由都把「路由 id」和「共享身份 `workbuddy`」两个键登记进注册表：模型身份两边相同，`isSameModel` 成立，换区不再降级；路由 id 仍独立（`workbuddy` / `workbuddy-global`），
各自指向自己的 shim、目录与凭据，一侧故障不会带走另一侧，模型选择器仍是两组。

**仍会看到的变化。** 同区域内换模型仍会降级（model 那条腿确实变了，旧 thinking 签名未必对新模型有效）；升级前已录进历史的消息带着旧的按区域 id，重放时仍按旧规则降级——这种历史只会越聊越少。

**thinking 变成正文还会影响内容。** 被降级的 thinking 不是丢弃，而是改写成正文（答案通道），于是**另一个模型的内部工作笔记会作为本轮回答呈现**；模型读到「过去的思考都是正文」
后，后续轮次会继续把计划写进正文。

- **跨 provider 的外来 thinking 无条件丢弃，不设开关**：这些块由宿主重建成 `dsh-foreign`，不带 `thinkingSignature`，无法作为带签名的 reasoning 重放；
  网关正好扫描 assistant 正文，整轮会以 `11128` 被拒，所以丢弃是纠正不是偏好。
- **`dropForeignThinking` 开关（默认关闭）只管同一路由内换模型**（如 `hy3` → `deepseek-v4.1-flash`）：那块内容由本插件自己提供，是否删掉属于偏好；
  关闭路径一个字节都不变。
- 修复跑在 `alignAssistantIdentities` **之后**——国际区自己的轮次也带 `api: 'dsh-foreign'`，先诊断会误删它自己的推理。
- 已经写进历史的坏轮次不会被追溯修复；想彻底摆脱，换 provider 后新开会话最直接。

**上游兜底。** 修法在上游（让 `isSameModel` 认「provider 等价组」，而不是让插件伪装身份）。插件侧的 `src/context-rescue.ts`（4.8.0 起）
在**上游确认超限后按块折叠历史再重发**，而不是原样重放整段历史——后者正是「压缩请求自己超限 → 压缩死锁」的成因。

**调试。** 设 `WORKBUDDY_BODY_REPORT` 可抓一次 body 组成报告，只记计数、不记正文。它会持续追加（每区一份 `<region>.jsonl`，超过 32 MB 滚成 `.1`，
只留一份旧档）；排查完请关闭该变量并删除报告文件，不要长期开着。
