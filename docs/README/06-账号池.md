## 账号池
一台机器上往往登录过多个 WorkBuddy 账号。**账号池**把它收成一次点击：把要用的账号勾进池子，批量签到 / 测试；再打开**启用账号池**，请求失败时自动换号接着跑。**每个区域（国内版 / 国际版）各有独立一池**，
成员与目标模型互不影响；**签到只有国内版有**。
> 窄栏下账号表会变成堆叠卡片：内容列只有 564px（800px 面板减 188px 导航），表格宽度小于 700px 时每行改成三行（账号与操作各一行、中间三个事实共享一行），单行从 157px 降到 96px，账号名不再截断；宽栏形态未改。
### 开关控制什么
**它只控制「插件要不要自己决定」，不控制「你能不能操作」。**
| | 开启 | 关闭 |
| --- | --- | --- |
| 谁服务 | 排序自动选出（可用优先 → 快过期先花 → 积分高 → 凭据新） | 你在池里手动选「使用哪个账号」 |
| 请求失败 | 自动换下一个可用账号重试 | 不换号，如实报错 |
| 一键签到 / 测试 | 可用 | **仍然可用** |
| 目标测试模型 | 可改 | **仍然可改** |
最后两行是刻意的：签到与测试是手动动作，与「插件是否自动路由」是两件事；关掉账号池本该是「我手动来」，不是「什么都不许做」。手动选择在账号池区块里：关闭时显示「使用哪个账号」下拉，选定即生效；开启时不显示（那时由排序决定）。
账号的发现、勾选、签到、测试全集中在这一块。
**唯一的硬约束**：池里一个成员都没勾选时，批量动作一律拒绝——空池绝不退化成「对全部账号执行」，那是唯一会花掉你没授权积分的解读。
### 自动换号
  - **谁来服务由排序决定**：开启后每次请求都发给排序最靠前的可用账号，所以「当前使用」显示的是排序结果，不一定是你手动选的。
  - **换号判定**：429 限流、402 无积分、401 凭据失效、502 网关/网络会换号（都是某个账号的状态）；**HTTP 400 不换**（请求体换谁都是 400）；**流中途断开也不重试**（字节已发出，
  重放会让客户端看到两段拼接的回答）。每次换号在宿主日志留一行 `warn`。
  - **跳过已知不可用的**：限流冷却中、凭据被拒的成员不参与；**从没测过的按「默认可用」参与**。
  - **失败会被记下来**：撞上失败就写成该账号的测量（含上游给的重置时间），下一个请求直接从可用账号开始，不会每次都撞同一个限流账号。HTTP 400 例外（是请求不合法，记下来会白闲置一个好账号）；
  未勾选进池的也不记。
  - **手动选择不会被改写**：运行时覆盖决定「谁服务」，从不写回你保存的选择；关掉账号池你选的账号立刻生效。
### 排序规则
   1. **可用优先**：被判定不可用的（限流未恢复、凭据被拒、连通性失败）排最后，不参与选择。
   2. **快过期的积分先花**：3 天内到期的**排在前面、先到期的先排**，都在临期时限期积分多的优先。
   3. **积分高者优先**：无临期积分的账号里选积分最多的；积分只在新鲜读数（10 分钟内）时参与，普通选号只读缓存。
   4. **凭据更晚过期的优先**。
   5. 按账号 id 收尾，保证全序、可复现，不因账号表顺序变化而抖动。
> 第 2 条排在第 3 条前面，是因为此前严格字典序（先比总量、完全相等才比到期）让「快过期优先」从未生效——总量几乎从不恰好相等。代价是**临期 1 分**会排在**余额 5 万**前面：这不是缺陷，不花那 1 分它确定损失，余额 5 万下一轮还在；临期账号若不够跑完一个请求，由换号逻辑接手。
### 两个批量动作
  - **签到勾选的账号**：逐个签到。**签到前先查当天状态**，已签的标记「已签到」而**不发写入请求**（幂等）；单个失败只标记该行，不中断整批。
  - **测试勾选的账号**：对每个成员发**真实体积**探测（约 25k 输入 token，与模型行「测试」同一套 `probeModel`：限流按体积触发、恢复时间写在响应体）。默认目标是该区**倍率为 0 的免费模型**（不写死名字——`deepseek-v4.1-flash` 就从 0 变成过 0.11），
  也可指定模型；指定模型若已离开目录会明确拒绝（`target-model-stale`），不偷偷换。
测试指向免费模型时几乎不花钱但**不是零成本空转**；签到真实领取当日奖励。两个动作默认**只在你点按钮时执行**；「每天自动签到」是显式、默认关闭的开关，打开才是授权插件替你领（先读状态，已签不重复领）。
### 成员、选择与草稿
  - **成员默认空、显式勾选**：「本机有登录」不等于「要拿它去签到和花积分」；必须逐个勾选（或全选），空池直接拒绝批量动作。勾选是**草稿编辑**，点「保存」才落盘，未保存时按钮带 dirty 指示，
  切走或关掉卡片草稿仍在。
  - **账号一律在池里管**：成员勾选就是账号选择面，「重新检测账号」也在那块。旧的「账号选择」下拉已移除——池开启时由排序决定、下拉改了不生效却看似权威。区域状态行也随之调整：**池开启时不报某个账号名**（多账号同时登录是常态），
  只陈述本区可用、由池决定用谁；**池关闭时才报出那个账号**。状态行旁的圆点与 token 过期时间讲的是「本区能不能用」，与「谁在计费」是两件事。
  - **两个「保存」是刻意的**：模型管理一个、账号池一个，草稿域不同——合并后一次写入失败会连累另一边，共享「放弃」会在误点里丢掉两份草稿。两边都是**验证写入**（写不成功不丢草稿）。「保存中」
  转圈只覆盖这次已校验的写入：写入一落地就解除忙碌、丢草稿，随后的用量刷新只是显示——刷新慢或失败不会说成「没保存上」，只另附一行「已保存，但面板未能重新读取」。探测结果、冷却时间、当前轮换账号**不走草稿**（它们是插件高频写入的观测事实；
  草稿是覆盖式的，若观测也进草稿，手工点一次「保存」会把插件刚写的结果回退成旧值）。
### 出池与回池
| 探测结果 | 对轮换的意义 |
| --- | --- |
| 可用 | 可入选 |
| 被限流 | **暂时**出池，按上游给的重置时间自动回池（上游没说就 30 分钟兜底，**不编造倒计时**） |
| 积分耗尽 | 出池，后续正余额确认到账后回池；月度刷新时间不作恢复倒计时 |
| 连不上上游 / 失败 | **暂时**出池，30 分钟后自动回池（往往是网络抖动或上游 5xx） |
| 凭据被拒 / 模型不存在 | 出池，**只能手动「测试」回池**（一个要重登、一个本区不再提供，等待修不好） |
| 账号被上游限制使用 | **停权，等待修不好**：点名的是**这个账号**，所以自动换号**会**绕开它（与「渠道校验失败」相反——那条说的是请求，换号白烧额度所以不换）。出路只有手动「测试」：账号 id 是 `uin`/`uid` 的哈希，重登后仍是同一个 id、也不会清掉这条测量；上游解除限制后测一次通过才重新成为候选。不编倒计时，但停权只作用于候选资格——全池无可用账号时请求仍落到你保存的那个账号 |
「被限流」「连不上上游」都不等于不可用，这两种状态恰恰值得等：当成永久失效剔除，会丢掉池子里最能用的账号；池内成员全被这样剔除后，自动换号没有候选，你只会看到上游原始报错。
**自动恢复依据**：限流和瞬时故障按冷却规则回池。积分耗尽需要后续正余额作为到账证据：签到后立即核对、卡片刷新时也核对；没打开卡片时每次请求前只核对耗尽账号，同区至多每分钟一次、并发共享查询；已有可用账号时后台执行恢复，
全池无可用才等待查询，客户端断开解除等待。零余额、无效读数、查询失败均不解除旧失败，月度刷新时间经过也不解除。提示按有效签到状态显示「签到后重试」「明日签到后重试」或「等待积分补充」。恢复清的是最近失败记录、
显示「未测试」，不把余额到账伪装成模型测试成功。余额为零本身不排除账号（免费模型仍可用）；手动测试成功更新测试结论，普通聊天成功不写测试记录。
