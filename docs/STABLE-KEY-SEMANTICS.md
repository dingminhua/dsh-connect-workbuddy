# 稳定 `X-Conversation-ID` 的语义：路线 A（请求前缀派生的亲和键实验）

> 适用对象：`stableConversationId` 开启后由 `deriveStableConversationId(bodyJson)` 生成的值。
> 该开关自 **5.24.15 起默认 `true`**（#275：冻结单变量实验 + 维护者独立复现后翻默认）；设为 `false` 恢复每请求现生成的原形状。
> 本文件是该开关语义的**唯一权威定义**；`CHANGELOG.md` / `docs/DESIGN.md` / 实现注释均须与之一致。
> 本文不写任何真实账号、机器、路径值；账号一律称「账号A / 账号别名」，本机路径一律 `/Users/<you>`。

## 1. 决策：采用路线 A（最小范围）

保留「从请求正文前缀派生稳定值」的实现，但把它**准确定位为「请求前缀派生的亲和键实验」（affinity-key experiment）**，供使用者在受控条件下对照「稳定 `X-Conversation-ID` 与隐式前缀缓存命中之间的关系」。

- 它**不是**宿主 `sessionId`，**不是**官方会话标识，**不是**真正的会话稳定键。
- 它只是一个由请求内容决定的、在一次连续对话中尽量不变的请求头取值，目的是让「同一不变前缀 + 同一 `X-Conversation-ID`」这一组合可复现，便于单变量对照。
- 上游内部究竟是「按缓存键分区」「按路由亲和」还是二者混合，本文件及所有相关文档**不做机制断言**；本 PR 也不声称稳定 ID 能改善命中，改善与否须由使用者自行在指定构建/账号/模型/时间窗口下验证。
- 该开关最初以默认 `false` 落地，作为受控对照的可选能力；**默认值的推广属于单独决策**。5.24.15 依据 #275 的冻结单变量实验与维护者独立复现（87.1pp [81.9, 92.0]，BENEFIT_SUPPORTED）翻为默认 `true`。

路线 B（真正的会话稳定且互斥隔离，需要可信的宿主会话标识，例如由 DSH 透传 `sessionId`）能做到「整段会话稳定 + 不同会话之间互斥隔离」，但超出本次最小范围：**本次不采用，需另行设计并提交用户确认**。

## 2. 已知限制（路线 A 的固有属性，不是 bug）

1. **纯靠请求正文无法可靠区分正文完全相同的两个独立会话。** 若两个独立会话的「不变前缀」（`model` + 首条 `system` + 第一条真实 `user`）完全相同，它们会**共享同一个派生键**。这是路线 A 的已知限制；文档不得对会话之间的隔离性或互斥性作任何肯定宣称。
2. **键可能在会话中途改变**，因为派生自请求内容而非会话身份。以下情况都可能换键：
   - 上下文压缩 / 摘要重写（首条 `system` 或首条真实 `user` 变化）；
   - 首条消息被删除、重排，或注入块被当作真实首问；
   - 首问内容变化（用户改写首个问题）；
   - 模型切换（`model` 字段变化）；
   - 会话分叉 / 恢复 / 重放（前缀被重建）。
   因此**不得宣传为「整段会话稳定」**，也不得对 warm 轮的命中作确定性宣称。
3. **不把本键描述为等价于原生 `sessionId` 的身份**：原生 WorkBuddy 把 `X-Conversation-ID` 绑定为整个会话不变的 `sessionId`；本插件的稳定值派生自请求前缀，二者来源、生命周期、隔离性都不同。
4. **UUID 只宣称「符合 v4 形状」**：派生值被格式化成 v4 形状的 UUID 字符串，仅此而已；**不宣称是随机 UUIDv4**，不宣称是加密安全随机，也不宣称是任何官方会话 ID。

## 3. 派生输入的编码规则

- 输入元组：`(model, 首条 system, 第一条真实 user)`，跳过宿主注入的 `user` 块；追加的历史、工具调用、回复**不参与哈希**，否则每轮都会变。
- **NUL 歧义已修**：元组使用**无歧义编码**（JSON 数组），不同元组不会因为字段内出现 NUL 字符（U+0000）或简单拼接而产生相同输入。即三元组（a、b、c）与把 a、b 用 NUL 拼成一个字段的二元组之类不会碰撞。
- **多模态**：首问含非文本 part（如图片、tool 结果）时，按**规范化完整内容**编码，而不是只取文本片段；**纯图片首问**显式处理——不再隐式忽略非文本 part、不再静默回落到随机 ID。若规范化后仍无法派生（缺字段 / 无法解析），则**显式回退**到每请求现生成，并把该回退路径记入本文件与实现注释。

## 4. 默认值与默认值纪律

- `stableConversationId` 自 5.24.15 起默认 `true`：默认路径从请求体不变前缀派生 `X-Conversation-ID`，以复用上游前缀缓存。设为 `false` 则回到「每请求现生成三件套」的原形状，相对基线 commit `d03282f` 的默认路径请求构造逻辑不变（随机 ID 逐次不同；仅相对该基线描述，不覆盖更早版本）。
- 开关只影响 `X-Conversation-ID`；`X-Conversation-Request-ID` / `X-Conversation-Message-ID` / `X-Root-Request-ID` 始终每请求现生成。
- 配置在插件挂载时采样一次，改动后需重载插件才生效。
- **默认值不是实验成功的自动结果，而是单独决策**：最初落地为 `false`，5.24.15 经 #275 的独立复现后才翻为 `true`。该决策的证据边界见第 5 节，不外推、不作机制断言。
- 最初的 PR 只落地「可选开关 + 派生函数 + 离线 wire 级单测」，真实上游实验、安装/重载完整链路验证经由 #275 的冻结实验与维护者独立复现补齐。

## 5. 结论措辞纪律

本开关源自实验、现已默认开启，但相关叙述一律采用**限定措辞**，不得升级为机制证明或因果宣称：

> 在指定构建、账号别名、模型和时间窗口下，观察到稳定 `X-Conversation-ID` 与更高的隐式前缀缓存命中相关。该观察不能区分缓存键分区与路由亲和等内部机制，也不能外推到所有账号/模型；它不构成稳定 ID「导致」命中提升的证明。

以下类别的过强表述一律不得作为结论出现：对 warm 轮命中作确定性宣称、把内部机制当作已证明、把本键描述为等价于宿主会话标识、对会话之间的隔离性或互斥性作肯定宣称、对全部历史版本声称字节级一致、声称控制组排除了全部混淆、把工具输出状态词当作实验证实。

最初落地的 PR 不附带任何命中率实测数字；#275 的冻结实验与维护者独立复现提供了受控读数（见该 issue），但其口径仍是人工长前缀逐轮重发、**不等于真实多轮收益**。若使用者自行验证，须自行记录条件、限定范围并避免上述过强表述。

## 6. 术语对照

| 概念 | 路线 A（本次） | 路线 B（本次不采用） |
| --- | --- | --- |
| 键来源 | 请求正文前缀派生 | 可信宿主会话标识（如 `sessionId`） |
| 定位 | 亲和键实验 / 单变量对照 | 真正的会话稳定键 |
| 整段会话稳定 | 否（压缩/首问变化/模型切换/分叉都可能换键） | 是（需宿主保证） |
| 不同会话之间是否互斥隔离 | 否（相同前缀会共享键） | 是 |
| 是否等价于原生 `sessionId` | 否 | 视实现而定，需单独验证 |
| 是否需要宿主改动 | 否 | 是（需透传，另行设计 + 用户确认） |
| 默认值 | `false`，不因实验改变 | 不适用 |
